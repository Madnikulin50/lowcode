# Поверхность атаки платформы lowcode

Версия: 2026-10-13 · Ветка `2026.10.x` · Основа: код репозитория и результаты аудита ([SECURITY_AUDIT_FSTEC.md](../../SECURITY_AUDIT_FSTEC.md)).

Машиночитаемое представление: [fstec-attack-surface.yaml](fstec-attack-surface.yaml); сводные таблицы ФСТЭК — [fstec-tables.md](fstec-tables.md).

Документ перечисляет **все точки входа** в систему: сетевые порты, HTTP-маршруты, каналы ввода данных, интерфейсы выполнения кода, внешние зависимости и цепочку поставки. Для каждой точки указано, кто может её вызвать, какие меры уже есть и что остаётся. Угрозы и их оценка — в [threat-model.md](threat-model.md); категория значимости КИИ — в [kii-categorization.md](kii-categorization.md).

Условные обозначения аутентификации: **нет** — запрос принимается без проверки; **JWT** — Bearer-токен платформы; **сессия** — cookie auth-сервера; **секрет** — общий секрет в заголовке; **сеть** — защита только сетевым периметром.

## 2. HTTP-маршруты сервера (N1)

Монтирование — `server/app/servers.go`, `server/pkg/api/server/handlers.go`.

### 2.1. Доступны без аутентификации

| Маршрут | Назначение | Риск | Меры |
|---------|-----------|------|------|
| `/healthcheck`, `/version` | состояние и версия | раскрытие версии | — (рекомендуется закрыть на периметре) |
| `/auth/*` (логин, регистрация, сброс пароля, OAuth2, SAML) | вход пользователей | перебор, перечисление пользователей, фишинг | rate-limit токенов (`checkTokenRate`), политика паролей, CSRF (`SameSite=Strict`), cookie `HttpOnly`, MFA TOTP/Email OTP |
| `/auth` регистрация | саморегистрация | создание учётных записей посторонними | **в стандартном provision включена** (`provision/001_settings/auth.yaml`: `auth.internal.signup.enabled: true`); подтверждение email включается автоматически только при корректных SMTP-настройках — в промышленной среде отключить регистрацию |
| `/.well-known/openid-configuration` | метаданные OIDC | — | — |
| `/api/docs`, `/api/manual`, `/api/architecture` | встроенная документация (`docs.GetFS()`, `ManualFS()`, `ArchitectureFS()`), монтируется всегда | раскрытие устройства системы | закрыть на периметре в промышленной среде |
| `/sink/*` (Sink) | вход для внешних вызовов, запускает workflow | вызов workflow анонимом | URL подписывается (`signer.Sign`, HMAC-SHA256), подпись в параметре или пути, срок действия опционален; workflow выполняется от `run-as` |
| `/agents/enroll` | выдача токена агенту | подбор секрета, получение токена на 365 дней | маршрут существует только при заданном `AGENT_SHARED_SECRET`; сравнение секрета выполняется за постоянное время; **нет** ограничения частоты и срока токена короче года (см. A-3) |
| `/assets/*`, `/webapp/*` | статические файлы | обход каталога | путь нормализуется (`path.Clean`, п. 13 аудита) |
| `/scim/*` | провижининг пользователей | подмена учётных записей | включается флагом `SCIM.Enabled`; без заданного `SCIM.Secret` не монтируется |

### 2.2. Только с аутентификацией (`auth.HttpTokenValidator("api")`)

| Группа | Префикс | Что принимает |
|--------|---------|---------------|
| System | `/api/system/*` | пользователи, роли, настройки, DAL-соединения, APIGW, шаблоны отчётов, SCIM |
| Compose | `/api/compose/*` | модули, записи, страницы, графики, чат, RAG, цепочки правил |
| Automation | `/api/automation/*` | workflow, триггеры, сессии, промпты, навыки (skills), тесты AI-шагов |
| WebSocket | `/api/websocket/*` | подписки на события |
| Discovery / Federation | `/api/discovery/*`, `/api/federation/*` | включаются флагами |
| Gateway | `/api/gateway/*` | настраиваемые маршруты прокси к внешним сервисам (APIGW) |

Все группы проходят цепочку: `JWT middleware → rest/request (разбор) → service (RBAC + логика) → store/DAL`. Права проверяются в сервисном слое (`svc.ac.Can…`), а не только на маршруте.

Перечень зарегистрированных маршрутов можно получить так:

```bash
cd server && go run ./cmd/corteza serve --help   # опции
curl -s http://localhost:$HTTP_PORT/api/docs/ | head   # встроенная документация открыта всегда
```

## 3. Агенты (N4, N5)

Агенты — отдельные процессы с собственным HTTP API по контракту `lowcode.agent.v1` (`agents/sdk/service.go`).

Маршруты каждого агента: `GET /health`, `GET /api/meta`, `GET /api/skills/{handle}`, `POST /api/register`, `POST /api/jobs`, `GET /api/jobs`, `GET /api/jobs/{id}`, `GET /api/jobs/{id}/items`, `POST /api/call/{op}` и алиасы операций.

### Находки

| ID | Находка | Следствие | Рекомендация |
|----|---------|-----------|--------------|
| **A-1** | SDK не проверяет входящую аутентификацию: на роутере только `Recoverer` и CORS (`sdk/service.go`, `sdk/http.go`) | любой, кто достигает порт, запускает операции: сканирование сети (`scan-cidr`, `cmdb`), бэкап/восстановление (`backup`), расчёты | поставить общий секрет или проверку JWT платформы в middleware SDK; до этого — закрыть порты агентов сетью и не публиковать наружу |
| **A-2** | `Access-Control-Allow-Origin: *` на всех маршрутах агента | страница в браузере администратора (или DNS-rebinding) может вызывать агента на `localhost`/внутреннем адресе | ограничить `Origin` списком из конфигурации, убрать `*` |
| **A-3** | `/agents/enroll` выдаёт токен сервисного пользователя на 365 дней по общему секрету, без ограничения частоты | утечка секрета = долгоживущий токен; перебор не ограничен | ограничить частоту, сократить срок и добавить отзыв, привязать токен к агенту |
| **A-4** | Агенты ходят в платформу под identity `corteza-service` | компрометация одного агента даёт права сервисного пользователя на весь Compose | отдельный пользователь и роль с минимальными правами на каждый агент |
| **A-5** | У HTTP-серверов агентов нет `ReadHeaderTimeout` | медленные соединения занимают ресурсы | `http.Server{ReadHeaderTimeout}` в SDK |

Операции агентов с повышенным риском: сканирование сетей (`scan-cidr`, `cmdb`), запуск внешних процессов (`pkg/rag` — разбор PDF/CAD, `gonec`), чтение и запись файловых шар и БД (`backup`), растеризация PDF (`stroykontrol`).

## 4. Каналы ввода данных

| # | Канал | Формат | Где разбирается | Основные риски | Меры |
|---|-------|--------|-----------------|----------------|------|
| D1 | Загрузка файлов (вложения записей, версии файлов) | multipart, произвольные файлы | `compose/service/attachment.go`, `system/service/attachment.go` | вредоносное содержимое, зипбомба, полиглоты, ресурсы при обработке изображений | проверка типов, подписанные URL (HMAC-SHA256), версионирование; разбор изображений библиотекой `imaging` (CVE-2023-36308, DoS по crafted TIFF — остаточный риск) |
| D2 | Импорт записей (CSV/JSON/XLSX), Envoy YAML | файлы | `pkg/envoyx`, `compose/envoy` | тяжёлые данные, формульные инъекции в экспорт, prototype pollution в JS (`xlsx`) | лимиты, RBAC на импорт; `xlsx` на клиенте без патча (остаточный риск) |
| D3 | Тела REST-запросов (формы, JSON) | JSON, form | `*/rest/request` | `ParseForm` без лимита размера (G120), массовые параметры | точечный лимит не введён (в плане) |
| D4 | WebSocket | JSON | `pkg/websocket` | недоверенные клиенты, DoS | токен, ограничение по identity |
| D5 | Sink / webhooks | произвольный HTTP | `system/service/sink.go` | анонимный запуск workflow | настройки sink, `run-as` |
| D6 | Шаблоны отчётов и писем | Go-templates, HTML | `system/renderer` | SSRF через `inlineRemote`, SSTI | только `http(s)`, таймаут 15 с, лимит 10 МБ; **внутренние адреса не блокируются** (остаточный риск) |
| D7 | Промпты и AI-ввод (чат, AI-шаги workflow и цепочек, MCP) | текст | `compose/service/chat*.go`, `pkg/aiagent` | prompt injection, исполнение инструментов, утечка данных в LLM | подтверждение мутаций («да»), бюджет вызовов, область инструментов агента, трассировка; см. [threat-model.md](threat-model.md) раздел 5 |
| D8 | Навыки (skills) и библиотека промптов | Markdown/zip | `pkg/aiagent/skills*.go`, `automation/service/skill.go` | вредоносные инструкции, чтение вне каталога | лимиты (50 файлов, 100 КБ/файл), без исполнения скриптов, не-регулярные файлы пропускаются |
| D9 | Импорт OpenAPI / настроек APIGW | конфигурация | `system/service/apigw*.go` | прокси к внутренним адресам (SSRF) | настраивается администратором |
| D10 | Входящая почта / внешние провайдеры (OAuth2, SAML) | XML/JSON | `auth/saml`, `auth/external` | XML-подпись (XSW), подмена IdP | `goxmldsig` 1.6.0, проверка подписи |

## 5. Выполнение пользовательского кода

Наиболее чувствительная часть поверхности: платформа допускает код, написанный администраторами и разработчиками приложений.

| Механизм | Где | Кто может создать | Изоляция | Статус |
|----------|-----|-------------------|----------|--------|
| Скрипты Corredor (JS) | внешний процесс по gRPC | роль с правом на скрипты | отдельный процесс | оценить сетевую изоляцию `CORREDOR_ADDR` |
| `gonec` (1С-подобный интерпретатор) | `pkg/gonec` | MCP-инструмент `gonec_run` (выключен по умолчанию, `MCP_ENABLE_SCRIPTS=true`) | белый список импортов (`checkImports`, п. 5 аудита), внешние процессы | в промышленной среде не включать либо изолировать на уровне ОС (gVisor/контейнер) |
| Rule chains (`rulesgo`) | `pkg/rulesgo` | роль на цепочки; валидация `ValidateChain` | интерпретатор узлов | узел `gonec` без runner = no-op |
| Workflow (BPMN, функции `http`, `aiAsk`, …) | `automation/` | роль на workflow; запуск от `run-as` | права `run-as` | события с обязательным `run-as` |
| JS-выражения (`pkg/jsenv`) | `pkg/jsenv` | редакторы блоков | VM | — |

Запуск внешних процессов (G204): `pkg/gonec/engine.go`, `pkg/rag/parser*.go` — аргументы берутся из конфигурации и файлов, загруженных пользователями; рекомендуется запуск под отдельной непривилегированной учётной записью и с `seccomp`/read-only корнем.

## 6. Исходящие связи

| Назначение | Модуль | Управляет адресом | Риск |
|-----------|--------|-------------------|------|
| LLM (Ollama и др.) | `pkg/chat`, `pkg/aiagent` | администратор (`OLLAMA_URL`) | утечка данных записей в модель; подмена модели |
| Внешние HTTP из workflow и APIGW | `automation/`, `pkg/apigw` | автор workflow / администратор | SSRF, утечка данных |
| IdP (OIDC/SAML) | `auth/external` | администратор | подмена IdP |
| SMTP | `system/service/mail` | администратор | рассылка от имени платформы |
| MinIO/S3, СУБД клиента (DAL) | `pkg/objstore`, `pkg/dal` | администратор | доступ к чужим данным при ошибке в DSN |
| `http.DefaultClient` с `InsecureSkipVerify` | `pkg/http/default.go` | только при `SYSTEM_HTTP_CLIENT_TSL_INSECURE=1` | отключение проверки TLS — в промышленной среде держать выключенным |

## 7. Цепочка поставки

| Область | Состав | Контроль | Остаток |
|---------|--------|----------|---------|
| Go-зависимости | `server/go.mod`, `server/vendor` (≈ 180 модулей) | `govulncheck`, `osv-scanner` | `imaging` (LOW, без патча), `chi` v3 (тестовая зависимость) |
| JS-зависимости | 9 проектов `client3/lib/*`, `client3/web/*`, `server/webconsole` | `osv-scanner`, `yarn audit` | 182 вхождения: `xlsx`, `echarts`, `vitest`, `mxgraph` (требуют смены major или замены) |
| Образы | `pnp-lowcode`, `pnp-backup`, … (`FROM ubuntu:22.04`) | — | не сканировались (`trivy`), базовые образы не закреплены по digest |
| Сборка | `make`, Docker, Vite, rollup | `scripts/verify-ai.sh` (AI guard) | воспроизводимость сборки и подпись артефактов не оформлены |
| Расширения AI | модели Ollama, навыки (`AI_SKILLS_DIR`, remote skills из `/api/meta` агентов) | источники навыков перечислены в `SetSkillSource` | удалённые навыки приходят от агентов — доверять только своим |
