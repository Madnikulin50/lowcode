# AI guard — защита от регрессий после правок ИИ

`scripts/verify-ai.sh` — быстрый таргетированный прогон проверок, который показывает,
что правка ИИ ничего не сломала. Он смотрит только на затронутые файлы, поэтому
занимает секунды-минуты, а не полный прогон CI.

Проверка построена на принципе **только новые проблемы**: сборка, `go vet`, `go test`
и сборки webapp гейтят лишь то, чего нет в baseline (см. ниже). Иначе, из-за
изначально не «зелёного» репозитория, страж превращался бы в шум, и его перестали
бы запускать.

## Быстрый старт

```bash
make verify            # проверка изменённых файлов (staged + unstaged + untracked)
make verify.ci         # то же, но относительно merge-base с origin/HEAD
make verify.full       # полная сборка, тесты и адвайзори-проверки всего дерева
make verify.watch      # периодически повторять verify (интервал 5с)
make verify.hygiene    # только гигиена дерева, без сборки
```

Скрипт возвращает `0`, если блокирующих проблем нет, и `1` иначе — им можно
завершать `git`-хуки и CI-шаги.

## Режимы

| Режим | Что проверяется | Когда использовать |
|-------|-----------------|--------------------|
| `--staged` | только проиндексированные файлы | git `pre-commit` |
| `--changed` | staged + unstaged + untracked (по умолчанию) | после правки ИИ, вручную |
| `--ci` | изменения относительно merge-base с `origin/HEAD` (fallback `HEAD~1`) | PR / push в CI |
| `--full` | всё дерево: полная сборка, тесты, адвайзори-проверки | перед релизом, ночью |
| `--hygiene` | только гигиена дерева, без сборки | быстрый pre-flight |
| `--watch[=N]` | периодически (по умолчанию каждые 5с) повторять `--changed` | локальная работа с ИИ |

Дополнительные флаги:

- `--strict` — сделать предупреждения блокирующими;
- `--update-baseline` — записать текущие падения в baseline (принять как известные);
- `--verbose` / `-v` — печатать список выбранных файлов и пакетов.

## Что блокирует, а что только предупреждает

**Блокирующие гейты (только новые проблемы):**

- незавершённые merge-конфликты, забытые `.only` / `fit` / `fdescribe` в тестах,
  остатки `.orig` / `.rej`;
- сборка `server/cmd/corteza`;
- `go vet` изменённых Go-пакетов;
- `go test` изменённых Go-пакетов;
- `vite build` затронутых webapp (`client3/web/*`);
- тесты lib (`client3/lib/js`, `client3/lib/vue`).

**Предупреждения (не блокируют без `--strict`):**

- `go build ./...` — мёртвые/несобираемые пакеты (только в `--full`);
- `eslint` изменённых файлов затронутых webapp.

Файлы в `vendor/`, `node_modules/`, `dist/`, `cdist/`, `.vite/` не проверяются:
это сгенерированные каталоги, они дают тысячи ложных путей.

## Baseline известных проблем

`scripts/ai-guard-baseline.txt` — список проблем, которые уже есть в репозитории
и **не** считаются регрессией (нормализованные `go vet` замечания и имена падающих
тестов). Строки без `#` — записи, отсортированные и уникальные.

```bash
make verify.baseline   # принять текущие падения как известные
# полный baseline по всему дереву:
scripts/verify-ai.sh --full --update-baseline
```

Обновляйте baseline осознанно: это явное признание «эта проблема не моя». Если
проблема появляется снова после правки ИИ, она снова станет блокирующей.

## Аварийный обход

Если нужно пропустить проверку (например, диагностика инфраструктуры):

```bash
SKIP_AI_GUARD=1 make verify
```

## Периодическая проверка

**Локально** — `make verify.watch`: раз в интервал пересчитывает отпечаток рабочего
дерева и перезапускает `--changed` только при изменениях. Удобно держать в отдельном
терминале во время сессии с ИИ.

**В CI** — `.github/workflows/ai-guard.yml`:

- на `pull_request` / `push` в релизные ветки — `scripts/verify-ai.sh --ci`
  (только изменённое);
- по расписанию (ночью) — прогон тестов `server` (`make test.unit`) и lib
  (`client3/lib/js`, `client3/lib/vue`), чтобы поймать деградацию, внесённую серией
  правок без открытого PR;
- вручную через `workflow_dispatch`.

## Расширение тестов

Тесты — главный механизм, который ловит регрессии после ИИ. При добавлении
функциональности добавляйте тесты рядом с кодом:

- **Go** — `*_test.go` в том же пакете; общий AI-контракт
  (`server/pkg/aiagent/structured.go`) покрыт `structured_test.go`.
- **lib/vue** — `*.test.ts` рядом с модулем; запускается `vitest`
  (`client3/lib/vue/vitest.config.ts`, `globals: true` + алиас `corteza-lib/js/dist`).
- **lib/js** — `*.test.ts` рядом с модулем; запускается `mocha`.
- **webapp** — `yarn test:unit` в каталоге приложения.

Каждый новый тест автоматически попадает в гейт guard: он прогоняет тесты только
затронутых пакетов и lib.
