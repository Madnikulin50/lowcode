# Проверка ИД (АОСР) — Compose namespace + агент idcheck

Проверка первичной исполнительной документации (АОСР/АООК) против реестра
передачи ИД, формы КС-2 и нормативных требований. Пространство
`stroykontrol-id` хранит данные и показывает результаты; вся проверка — в
Go-агенте `agents/stroykontrol` (пакет [`idcheck/`](../idcheck)).

## Быстрый старт

```bash
cd agents/stroykontrol
go build -o bin/stroykontrol-web .
node compose_id/apply_id.mjs          # пространство, модули, страницы, rule chain, сид нормативки
./run.sh                               # агент на :8092 (POST /api/idcheck/run)
node compose_id/import_package.mjs "$HOME/Загрузки/Пример ПД и РД/ИД, реестр, КС-2" --only=/2.14.1.9/ --run
```

Дальше — карточка пакета: кнопка **«Запустить проверку ИД»** (rule chain
`stroykontrol-id-run` → `POST {IDCHECK_AGENT_URL}/api/idcheck/run`), поле
«Ход проверки» показывает текущий шаг, замечания/акты/сводка появляются
по мере обработки.

| Переменная / флаг | По умолчанию | |
|---|---|---|
| `IDCHECK_AGENT_URL` (apply_id.mjs, import_package.mjs) | `http://localhost:8092` | куда rule chain шлёт пакет |
| `--ollama` / `OLLAMA_URL` | `http://localhost:11434` | Ollama |
| `--vision-model` / `IDCHECK_VISION_MODEL` | `qwen3.5` | мультимодальная модель; пусто — без распознавания сканов |
| `--tesseract`, `--ocr-lang` | `tesseract`, `rus` | OCR страниц для классификации и подсказки модели; если не установлен — правила раскладки (стр. 1–2 акт, первая альбомная — схема, остальное — вложения) |
| `--classify-pages` | `false` | без tesseract классифицировать каждую страницу моделью (~45 с/стр на CPU) |
| `--max-attached` | `6` | сколько страниц вложений (сертификаты, протоколы…) на акт отдавать модели, `-1` — все |
| `--external` | `true` | онлайн-проверки ЕГРЮЛ / НРС |
| `--idcheck-cache` | `var/idcheck-cache` | растр, OCR, ответы модели (повторный прогон не распознаёт заново) |

## Замечания по месту

В карточках пакета, акта и замечания встроен просмотрщик агента
(`/?view=idcheck&packageID=|actID=|findingID=`, IFrame через маршрут
API Gateway `/gateway/agents/stroykontrol/*` → агент):

- слева — замечания, сгруппированные по актам / реестру / КС-2, фильтры по
  критичности (низкая — сомнения распознавания, по умолчанию скрыта), номеру
  проверки, акту и поиск; ↑/↓ или j/k — следующее замечание;
- справа — место замечания: **скан акта** с рамкой вокруг найденного
  значения (координаты слов из tesseract; значение ищется точно, затем
  нечётко, затем по подписи поля — «ИНН», «Приложения»…; если не найдено,
  страница помечается целиком), лента страниц с типом страницы и счётчиками
  замечаний; **реестр** с подсвеченной строкой и текстом замечания в ней
  (контекст ±3 строки или весь реестр); **реестр ↔ КС-2** по позициям.

Эндпоинты: `GET /api/idcheck/view?namespaceID=&packageID=|actID=|findingID=`,
`GET /api/idcheck/page?namespaceID=&actID=&n=` (JPEG страницы скана).
Рамки хранятся в поле замечания `bbox` (`x,y,w,h` в долях страницы).

Локальная разработка фронтенда: `.claude/launch.json` → `idcheck-viewer`
(Vite на :5181, `/api` проксируется на `AGENT_URL`).

## Модули

| handle | |
|---|---|
| `packages` | Пакет: реестр xlsx/pdf, КС-2 xlsx/pdf, акты (multi-file), статус, ход, итоги |
| `registry_rows` | Строки реестра (разделы, позиции ВРЦ, акты) с кол. 9–13 |
| `acts` | Акт: номер/дата из имени файла и из документа, п.1–п.7, приложения, вложенные сканы, схема, результат |
| `participants` | Представители из шапки акта: роль, ФИО, приказ, ID НРС |
| `findings` | Замечания: № проверки 1–8, критичность, ожидалось/фактически, страница, источник |
| `position_summary` | Проверка 8: Σ min(кол.12, кол.13) по позиции ↔ КС-2 ↔ кол.11 реестра |
| `organizations` | Кэш ЕГРЮЛ по юрлицам из актов |
| `nrs_specialists` | Кэш НРС по идентификационным номерам |
| `norm_docs` | Справочник нормативки: действует с/по, чем заменён, для каких работ обязателен. Засевается из `idcheck.DefaultNorms`, правки пользователя имеют приоритет |

## Проверки

| № | Что | Как |
|---|---|---|
| 1 | акт ↔ реестр | номер (нормализация: пробелы, «№», лат./кир. двойники, «ОП№3ИССО»), дата, объёмы п.1 (или схемы) ↔ кол.12/13; номер в реестре ↔ позиция, под которой он стоит; акты реестра без файла |
| 2 | приложения ↔ п.3/п.4 ↔ сканы | документы п.4 есть в приложениях; приложения найдены среди вшитых сканов; даты не позже акта; срок годности/действия ≥ даты работ п.5 |
| 3 | шифр РД | п.2 = п.6 = основная надпись исполнительной схемы |
| 4 | объём | п.1 ↔ схема (проект и факт) |
| 5 | нормативка п.6 | действует на даты работ (справочник), достаточность по видам работ (`work_tags`), наличие ссылки на РД |
| 6 | представители | приказ не позже акта и начала работ («из будущего»), ID НРС у стройконтроля, ID есть в НРС и не исключён |
| 7 | юрлица | контрольные числа ОГРН/ИНН; ЕГРЮЛ: найдено, наименование, ИНН↔ОГРН, прекращение деятельности, регион адреса |
| 8 | реестр ↔ КС-2 | по позициям Σ min(12,13) ↔ количество КС-2 |

Источник замечания: `det` — детерминированно по извлечённым данным,
`ext` — внешний реестр. Данные из сканов извлекает модель — при
сомнительном замечании (например, дата приказа «2032») сверяйтесь со
сканом: ошибка может быть в распознавании.

## Ограничения

- **Скорость.** Замер на CPU (16 ядер, без GPU), qwen3.5 9.7B: стр. 1–2
  акта — ~17 мин, схема — ~5 мин, страница вложения — ~5–6 мин; акт целиком
  (акт + схема + 6 вложений) ≈ 50 мин, полный пакет из 44 актов — ~1.5 суток.
  Для реальной работы нужен GPU-хост Ollama (`--ollama=`); на CPU — ночной
  прогон и/или `--max-attached=0`. Ответы модели кэшируются: повторная
  проверка пакета (после правки реестра, справочника нормативки) — секунды.
- **НРС** (nrs.nostroy.ru) показывает ФИО и даты картинками — читаются
  только наличие записи и статус «Действует/Исключён»; дату исключения
  относительно даты акта нужно сверить вручную.
- **ЕГРЮЛ** (egrul.nalog.ru) без ключа отдаёт наименование, ИНН/ОГРН,
  регион и дату прекращения, но не полный адрес — адрес сверяется по региону.
- Справочник нормативки — стартовый, не юридический источник: даты
  введения/отмены стоит сверить и дополнить в модуле «Нормативные документы».
