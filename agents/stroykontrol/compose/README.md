# Стройконтроль ПТО — Compose namespace

Пространство для трёх ТЗ из `Документ2.docx` (ПТО + сметный отдел строительной организации):

1. **Сравнение ПД и РД** — сверка PDF проектной и рабочей документации.
2. **Проверка исполнительной документации** — сопоставление загруженных файлов ИД с реестром.
3. **Проверка формирования ВОИСР** — сверка объёмов/стоимости ВОИСР со сметной документацией.

Паттерн тот же, что у `agents/invest/compose`: `apply.mjs` идемпотентно создаёт namespace / модули / страницы по REST API Compose (обновляет по `handle`, id сохраняются).

## Apply

Сервер должен быть поднят на БД `test11` (сейчас — `bin/test11 serve-api`, слушает `:3333`, API-only без встроенного webapp).

```bash
cd agents/stroykontrol/compose
COMPOSE_DSN='postgres://postgres:Zse45rdx@127.0.0.1:5432/test11?sslmode=disable' \
  node apply.mjs
```

| Variable | Default |
|---|---|
| `COMPOSE_API` | auto-detect `http://localhost:3333/api/compose` → `/compose` |
| `TOKEN` | обмен refresh-токена из Postgres (см. `helpers.mjs: mintToken`) |
| `COMPOSE_DSN` | нужен для минта токена и как первый кандидат; по умолчанию перебирает test10/test9/test3 |

Пишет `applied.json` с ID (namespace/модули/страницы).

Сервер `test11` не отдаёт webapp (только API) — чтобы открыть пространство визуально в Compose Studio/Builder, нужно указать webapp (dev-сервер vite или собранный бандл) на `COMPOSE_API=http://localhost:3333`.

## Модель

| Модуль (`handle`) | Роль |
|---|---|
| **Объекты** (`objects`) | НСИ: строительный объект — общий контекст для всех трёх задач |
| **Сравнения ПД/РД** (`pd_rd_comparisons`) | Задание на сравнение: файл ПД, файл РД, статус, % схожести, отчёт |
| **Расхождения ПД/РД** (`pd_rd_discrepancies`) | Построчные расхождения: страница, тип, критичность |
| **Реестр ИД** (`id_registry`) | Эталонный список требуемых документов ИД по объекту |
| **Файлы ИД** (`id_files`) | Загруженные файлы + распознанные реквизиты + статус сопоставления с реестром |
| **Проверки комплектности ИД** (`id_check_runs`) | Итог прогона: всего/загружено/отсутствует/несоответствий |
| **Позиции смет** (`smeta_items`) | Импортированные строки сметной документации |
| **Позиции ВОИСР** (`voisr_items`) | Позиции ВОИСР подрядчика, привязка к смете |
| **Результаты проверки ВОИСР** (`voisr_check_results`) | Сравнение объём/сумма по ВОИСР vs смета, статус |

Страницы: **Дашборд** (метрики) + список + карточка на каждый модуль (карточки скрыты из сайдбара, `visible: false`).

## Тестовые данные

```bash
cd agents/stroykontrol/compose
COMPOSE_DSN='postgres://postgres:Zse45rdx@127.0.0.1:5432/test11?sslmode=disable' \
  node seed.mjs
```

Генерирует ≥100 (по умолчанию 120, `SEED_OBJECTS=`) объектов строительства, и на каждый — полный комплект документов: реестр ИД, загруженные файлы ИД (с реальными вложенными `.docx` и статусом сопоставления с реестром), сравнение ПД/РД (тоже с вложенными файлами ПД и РД + расхождения по страницам), позиции сметы и ВОИСР со сверкой объёмов/сумм. Идемпотентно — при повторном запуске, если объектов уже достаточно, ничего не досоздаёт (`SEED_FORCE=1` — досеять поверх). `filegen.mjs` — генератор минимальных `.docx`-вложений и загрузка через `/record/attachment` (тот же приём, что в `agents/invest/compose/seed_files.mjs`).

Итог одного прогона (120 объектов, ~9 сек): 3587 записей — `id_registry` 752, `id_files` 754, `pd_rd_comparisons` 155 (+282 расхождения), `smeta_items` 680, `voisr_items` 362 (+362 результата проверки), `id_check_runs` 120.

## Не реализовано в этом apply (нужна отдельная проработка)

Сам apply создаёт только структуру данных (namespace/модули/поля/страницы). Ничего из следующего не реализовано:

- Разбор PDF (наложение страниц, текстовое сравнение, OCR) — п. 4.1.1–4.1.3 ТЗ №1.
- Импорт реестра ИД (XLSX/CSV/XML) и распознавание файлов ИД — п. 4.1.1–4.1.3 ТЗ №2.
- Парсинг смет (XLSX, Гранд-Смета `.gsf/.gsp`, АРПС) и автосопоставление с ВОИСР — п. 4.1.1–4.1.4 ТЗ №3.
- Формирование отчётов в PDF/DOCX/XLSX.

Это отдельные бэкенд-сервисы (по аналогии с `agents/invest` → `invest-engine`/`calc-evm`) или rule chains с HTTP-узлами; данные для их результатов поля модулей уже держат.
