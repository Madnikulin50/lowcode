# Chat & MCP conventions

## Tech stack
- **Ollama** runs on `http://localhost:11434` (override: settings `ai.ollama-url` → `OLLAMA_URL` → `OLLAMA_HOST`)
- **Maps**: Leaflet `CMap` tile URL from settings `ui.map.tileURL` (empty → public OSM CDN); admin **UI → Location → Map tiles** for offline/local tileserver
- **Default model**: `qwen3:8b` (`server/pkg/chat` `DefaultModel`; override via `CHAT_MODEL`, `<model>…</model>`, or admin **System → AI models** `ai.roles.*`)
- **Model override**: wrap `<model>modelname</model>` in prompt; admin catalog `ai.catalog` filters `/chat/models`
- **LLM client**: `github.com/cloudwego/eino-ext/components/model/ollama` in `server/pkg/chat/client.go`

## Chat tools (`server/compose/service/`)

### Static tools (`chat_tools.go` — `AllChatToolDefs()`)
18 tools: read/list/search/create/update/delete for modules, pages, charts.
Parameters are flat strings. Return JSON or user‑friendly text.
List functions return entity set; on empty set return `"No X found"` text.

### Dynamic per‑module tools (`chat.go` — `getTools()`)
Generated at runtime by querying `DefaultModule.Find`:
- `show_module_{handle}`, `module_search_{handle}`
- `module_{handle}_records`, `module_{handle}_create_record`, `module_{handle}_update_record`, `module_{handle}_delete_record`

`module_create_record` with empty `values` prints available fields.

### Confirmation
`needsConfirm()` triggers on `create_` / `delete_` prefixed tools.
Flow: LLM suggests action → stream asks for "да" → re‑entry with tool call.

## MCP handlers (`server/compose/mcp/handlers/`)

### Static tools (`modules.go`, `pages.go`, `charts.go`)
Same 18 CRUD tools as chat, with `namespaceID` as explicit param.

### Dynamic per‑module tools (`records.go` — `initModuleRecords()`)
Generated at startup, mirrors chat dynamic tools:
- `module_{handle}_records`, `module_{handle}_search`, `module_{handle}_create_record`, `module_{handle}_update_record`, `module_{handle}_delete_record`

### Transport
- STDIO: optional (`MCP_STDIO=true`)
- SSE: optional (`MCP_SSE_ADDR=:9090`)
- See `server/compose/mcp/index.go`

### Shared helpers (`ctrl.go`)
- `withAuth(ctx)` — injects auth identity
- `getString/parseUint64/argsMap` — extract typed args from `CallToolRequest`
- `jsonResult(textResult/errorResult)` — wrap response

## Adding a new entity
1. Create `chat_{entity}.go` handlers in `service/` with `chat{Action}{Entity}` funcs
2. Add tool defs in `service/chat_tools.go` → `AllChatToolDefs()` includes them
3. Create `handlers/{entity}.go` in `mcp/handlers/` with `init{Entity}()` + handler funcs
4. Add `init{Entity}(ctx, s)` call in `handlers/index.go`

- **«Кнопка Следующая запись не работает» (2026-08-19)**: на странице записи (`/ns/cmdb/pages/{page}/record/{recordID}`) клик по «Следующей» ничего не делал. **Причина — регрессия Vue Router 2→3**: `handleRedirectToPrevOrNext` в `views/Public/Pages/Records/View.vue:697` и `views/Admin/Modules/Records/View.vue:321` делал `router.push({ params: { ...route.params, recordID } })` БЕЗ `name`/`path` — в Vue Router 3 такое навигировало по текущему маршруту, в Vue Router 4 (`router.push` без name/path → пустой path) навигация молча не происходит (warning в консоли). **Фикс**: `router.push({ name: route.name, params: { ...route.params, recordID } })` в обоих файлах. **Продолжение (URL менялся, страница не обновлялась)**: в публичном `Records/View.vue` при миграции был ПОТЕРЯН prop `recordID` (в Vue 2 он приходил из `mixins/page.js:23` через route-props `props: r => ({...r.params})`), а заменяющий его computed `recordID` (строка ~336) имел приоритет `record.value?.recordID` над `route.params.recordID` → при навигации A→B: route-param уже B, но `record.value` ещё A → computed возвращал A → `uniqueID` (строка ~404) не менялся → watch не срабатывал → refresh() не вызывался. **Фикс**: `recordID` добавлен в `defineProps` (`{ type: String, default: '' }`, как в admin-версии, где prop есть и работает) + computed с приоритетом `props.recordID` → `route.params.recordID` → `record.value?.recordID` (фолбэк для модала `Modal.vue`, который передаёт `:record-i-d="recordID"`; на plain-странице route-параметра нет). Admin-версия не была сломана (prop объявлен, `uniqueID=[moduleID, recordID, edit]`). Сборка compose (37.13s) — OK. **Правило 1: Vue Router 4 — `router.push({params})` без `name`/`path` не навигирует; всегда указывать `name` (или `path`). Правило 2: при миграции Vue 2 mixin-props (route-props) — проверять, что prop остался в `defineProps`; computed-замена с приоритетом `record.value` маскирует смену route-параметра**
