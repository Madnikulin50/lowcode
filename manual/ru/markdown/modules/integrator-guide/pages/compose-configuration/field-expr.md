# Выражения полей

<a id="value-expressions"></a>
## Выражения значений

Выражения значений вычисляют значение поля на основе предоставленного выражения.
Выражение значения — это простое выражение, результатом которого является одно значение.
Если ваше поле является мультизначным, вам нужно вернуть массив элементов.

Обратитесь к [Expr](modules/integrator-guide/pages/compose-configuration/expr/index.md) за подробностями о написании выражений.

!!! important
    В настоящее время вы можете использовать только значения текущей записи.
    Ссылки пока не поддерживаются.
    Если вам нужно ссылаться на данные из нескольких записей, вместо этого используйте [скрипты автоматизации](modules/integrator-guide/pages/compose-configuration/automation/automation-scripts/index.md) или [рабочие процессы](modules/integrator-guide/pages/compose-configuration/automation/workflows/index.md),


.Доступные переменные в контексте вычисления:
[cols="1s,5a"]
|===

| [#values-ctx-old]#[values-ctx-old,`old`](#values-ctx-old,`old`)#
|
Переменная `old` ссылается на исходную запись.
Задаётся только при обновлении поля.

| [#values-ctx-new]#[values-ctx-new,`new`](#values-ctx-new,`new`)#
|
Переменная `new` ссылается на текущую запись.

| [#values-ctx-value]#<<values-ctx-value,`<field-name>`>>#
|
Строка или массив строк с текущими значениями полей.
Если имя поля совпадает с какой-либо из системных переменных, обратитесь к значению через [values-ctx-new,new["field*name*here"]](#values-ctx-new,new["field*name*here"]).

|===

.Пример выражения, вычисляющего цену с налогом:
```
```
price * 1.25

.Пример выражения, формирующего полное имя:
```
```
trim(firstName + " " + lastName)

.Пример вычисления мультизначного выражения:
```
```
["foo", "bar", "baz"]

<a id="value-sanitizers"></a>
## Санатизаторы

Санатизаторы изменяют значение поля, чтобы очистить (санитизировать) данные перед сохранением.
Санатизатор — это простое выражение, результатом которого является одно значение.

!!! important
    Санатизаторы выполняются несколько раз: один раз перед отправкой данных в шину событий (corredor и рабочие процессы) и второй раз непосредственно перед отправкой записи в API.


Обратитесь к [Expr](modules/integrator-guide/pages/compose-configuration/expr/index.md) за подробностями о написании выражений.

По своей природе санатизаторы **не должны** приводить к ошибке.
Если ошибка возникает, она регистрируется в журнале действий, и операция продолжается.

Если вы определяете несколько санатизаторов, они выполняются в указанном порядке.

.Пример санатизатора, ограничивающего длину текста:
```
```
length(value) > 5 ? substr(value, 0, 5) + "..." : value

.Доступные переменные в контексте вычисления:
[cols="1s,5a"]
|===

| [#sanitizer-ctx-value]#[sanitizer-ctx-value,`value`](#sanitizer-ctx-value,`value`)#
|
Переменная `value` ссылается на текущее значение.

|===

<a id="value-validators"></a>
## Валидаторы

Валидаторы проверяют значение поля, вызывая ошибки, когда значение недействительно.
Валидатор — это простое выражение, результатом которого является одно значение: `true` или `false`.
Проверка значения считается недействительной, когда выражение возвращает `true`.

Валидаторы не могут изменять значение.

Встроенные валидаторы полей можно отключить; валидаторы обязательности и уникальности мультизначных значений отключить нельзя.

Если вы определяете несколько валидаторов, они выполняются в указанном порядке.

!!! important
    Валидатор поля останавливается при возникновении первой ошибки.
    Например, если мы определим валидаторы `A`, `B` и `C`, и валидатор `A` вызовет ошибку, валидаторы `B` и `C` не будут выполнены.


.Проверочные выражения не выполняются, когда:
- значение не изменено,
- значение отсутствует.

!!! tip
    Используйте флаг required для проверки обязательных значений.


.Доступные переменные в контексте вычисления:
[cols="1s,5a"]
|===

| [#validator-ctx-value]#[validator-ctx-value,`value`](#validator-ctx-value,`value`)#
|
Переменная `value` ссылается на текущее значение.

| [#validator-ctx-oldvalue]#[validator-ctx-oldvalue,`oldValue`](#validator-ctx-oldvalue,`oldValue`)#
|
Переменная `oldValue` ссылается на исходное значение.
Задаётся только при обновлении поля.

| [#validator-ctx-values]#[validator-ctx-values,`values`](#validator-ctx-values,`values`)#
|
Переменная `values` ссылается на все значения записи (`values.<field-name>`).
Вы можете использовать её для написания валидаторов, учитывающих контекст.

|===

.Пример валидатора для проверки длины текста:
```
```
length(title) < 5
