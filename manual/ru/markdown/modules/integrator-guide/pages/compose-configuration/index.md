# Конфигурация Low Code

LowCoooode предоставляет мощную Low-Code платформу разработки, позволяющую с лёгкостью настроить ваше приложение.
LowCoooode Low Code позволяет расширить LowCoooode и поддержать потребности вашего бизнеса.

С помощью LowCoooode Low Code мы определяем логическую структуру данных, то, как данные отображаются, и то, как они должны визуализироваться.
Вторая часть — это процесс [автоматизации](modules/integrator-guide/pages/compose-configuration/automation/index.md), который позволяет реализовать собственную бизнес-логику и автоматизировать задачи.

Если вы хотите узнать больше о конкретной теме, обратитесь к подразделам раздела menu:Low-Code Platform Developer Guide[Конфигурация Low Code].

## Конфигурация приложения

### Создание нового пространства имён

**Пространство имён** — это контейнер для конфигурации и данных, специфичных для приложения, такого как CRM.
Пространство имён использует [config-modules,модули](#config-modules,модули) для определения структуры данных, [config-pages,страницы](#config-pages,страницы) для определения того, как данные отображаются, и [config-charts,диаграммы](#config-charts,диаграммы) для визуализации данных.

!!! important
    Пространство имён *не может* напрямую обращаться к данным из другого пространства имён.
    Если это необходимо, рассмотрите реализацию этого взаимодействия программным способом с помощью [автоматизации](modules/integrator-guide/pages/compose-configuration/automation/index.md).

<a id="generate-synthetic-data"></a>
### Генерация синтетических данных для модуля

LowCoooode предоставляет инструмент для генерации синтетических данных для модуля.
Вы можете использовать его для генерации большого объёма данных для модуля, чтобы протестировать производительность приложения или продемонстрировать реализацию.

В настоящее время инструмент доступен только в интерфейсе командной строки (CLI) и поддерживает генерацию синтетических данных для записей Low Code (`compose records synthetic`) и пользователей (`users synthetic`).

Сгенерированные записи помечаются флагом `synthetic:true` в поле meta записи, а у пользователей в начале handle добавляется префикс `synthetic_` и домен электронной почты `synthetic.tld`.

#### Использование

.Показать справку для генератора синтетических записей Low Code:
```shell
```
lowcode-server compose records synthetic --help

.Сгенерировать 10 лидов в пространстве имён crm:
```shell
```
lowcode-server compose records synthetic generate --namespace crm --module lead --total 10

.Удалить все синтетические записи в модуле leads в пространстве имён crm:
```shell
```
lowcode-server compose records synthetic rm --namespace crm --module lead

### Создание страниц записей

**Страница записи** определяет, как данные представляются пользователю при просмотре, создании и редактировании записей этого модуля.
Страница записи состоит из серии блоков страницы, которые определяются с помощью [page-builder,конструктора страниц](#page-builder,конструктора страниц).

!!! important
    Если ваш модуль не определяет страницу записи, вы не сможете создавать или обновлять его записи через пользовательский интерфейс.
    
    Вы по-прежнему можете просматривать его записи, создавать записи с помощью встроенных списков записей, API или [автоматизации](modules/integrator-guide/pages/compose-configuration/automation/index.md).


Страница записи привязана к указанному модулю и к записи, на которую она указывает.
Это позволяет настраивать блоки страницы, чтобы они реагировали на текущую просматриваемую запись для динамической фильтрации ресурсов.

!!! tip
    Вы можете использовать [макеты страниц](modules/integrator-guide/pages/compose-configuration/compose-configuration/page-layouts.md) для ещё большей гибкости в том, как пользователи взаимодействуют с данными.

<a id="config-charts"></a>
### Создание диаграмм

**Диаграмма** определяет, как визуализируются записи конкретного модуля.
Диаграмма привязана к вашему модулю и позволяет агрегировать и преобразовывать данные, которые затем визуализируются на диаграмме.

!!! note
    Одна диаграмма может отображать только записи одного модуля.


Если вы настраиваете новое пространство имён, вам предоставляется экран онбординга, с которого вы можете нажать на кнопку btn:[Create Chart], чтобы создать свою первую диаграмму.

Если вы хотите добавить дополнительные диаграммы или настраиваете уже настроенное пространство имён, перейдите в меню menu:Admin panel[Charts], затем нажмите на кнопку btn:[New Chart].

### Создание списковых страниц

**Списоковая страница** определяет, как приложение представляется пользователю при взаимодействии с ним.
Списоковая страница состоит из серии блоков страницы, которые определяются с помощью [page-builder,конструктора страниц](#page-builder,конструктора страниц).

В отличие от страниц записей, списковые страницы шире и привязаны только к тому пространству имён, в котором они находятся.
Они являются универсальными и используются для предоставления доступа к различным страницам записей через списки записей, панели мониторинга и другие макеты.

При настройке нового пространства имён вам предоставляется экран онбординга.
Оттуда вы нажимаете на кнопку btn:[Build Page], чтобы создать свою первую страницу.

!!! tip
    Вы можете использовать [макеты страниц](modules/integrator-guide/pages/compose-configuration/compose-configuration/page-layouts.md) для ещё большей гибкости в том, как пользователи взаимодействуют с данными.


Если вы хотите добавить дополнительные страницы или настраиваете уже настроенное пространство имён, перейдите в меню menu:Admin panel[Pages] и нажмите на кнопку btn:[New Page].
Оттуда вы можете нажать на кнопку btn:[Page builder], чтобы войти в [page-builder,конструктор страниц](#page-builder,конструктор страниц)

## Поля модуля

**Поле модуля** определяет форму записей модуля (какие параметры мы будем хранить), тип данных конкретных параметров, а также дополнительные настройки, управляющие поведением поля.
Каждый модуль может иметь несколько полей модуля.

Чтобы изменить поля модуля, перейдите в меню menu:Admin panel[Modules] и нажмите на модуль, который хотите изменить.
Поля модуля перечислены в разделе "manage module fields" ниже метаданных модуля.

.Подробный разбор полей модуля:
[cols="1s,5a"]
|===

|
Имя поля определяет, как значение хранится внутри системы и какой ключ используется при доступе к значению из автоматизации.

!!! caution
    После того как модуль заполнен хотя бы одной записью, имя не может быть изменено.


Имя поля должно быть коротким и описательным.
Существует **ограничение в 64 символа**.

.Имя поля должно соответствовать следующим ограничениям:
1. начинаться с символа,
1. содержать не более 64 символов,

### Конфигурация обычных диаграмм

.Обычные диаграммы включают:
- столбчатые диаграммы
- линейные диаграммы
- круговые диаграммы
- кольцевые диаграммы

[cols="1s,5a"]
|===

| [#chart-config-generic-module]#[chart-config-generic-module,Module](#chart-config-generic-module,Module)#
|
Модуль определяет источник данных (какие записи использовать) для диаграммы.
Диаграмма может отображать только записи того же пространства имён, в котором была создана диаграмма.

| [#chart-config-generic-filter]#[chart-config-generic-filter,Filter](#chart-config-generic-filter,Filter)#
|
Фильтр позволяет определить, какие записи вы хотите показать на диаграмме.
Например, вы хотите агрегировать лиды, созданные за последний месяц.

Выпадающее меню предоставляет вам выбор наиболее распространённых фильтров.
Нажмите на флажок "customize filter checkbox", если хотите изменить выбранный фильтр или написать свой собственный.
Обратитесь к [справочнику QL](modules/integrator-guide/pages/compose-configuration/accessing-lowcode/ql.md) за подробностями об определении фильтров.

| [#chart-config-generic-yxs]#[chart-config-generic-yxs,Y-axis](#chart-config-generic-yxs,Y-axis)#
|
Раздел оси Y позволяет настроить положение оси (слева или справа), подпись, а также минимальные и максимальные значения.

| [#chart-config-generic-dimension]#[chart-config-generic-dimension,Dimensions](#chart-config-generic-dimension,Dimensions)#
|
Раздел измерений позволяет указать, какое поле должно использоваться для построения измерения; оси X.

!!! note
    Текущая реализация допускает только одно измерение на диаграмму.


.В качестве полей измерений можно использовать только простые однозначные поля:
- `DateTime`
- `Select`
- `Number`
- `Bool`
- `String` с отключённым редактором форматированного текста.

Поля типа `DateTime` также позволяют определить функцию группировки.

| [#chart-config-generic-metric]#[chart-config-generic-metric,Metrics](#chart-config-generic-metric,Metrics)#
|
Раздел метрик позволяет указать, какое поле должно использоваться для определения значения каждого измерения и как оно должно быть отображено.

В качестве полей измерений можно использовать только числовые поля.
Специальное поле `count` возвращает количество записей, соответствующих параметрам конфигурации.

******
Здесь настраивается функция пост-обработки; она позволяет преобразовывать значения, сгенерированные отчётной системой.
Они записываются в виде простых JavaScript-выражений, которые возвращают одно число на основе двух переменных.

- `m`: значение предыдущей записи измерения (для первой записи значение равно `undefined`)
- `n`: значение текущей записи измерения

.Пример, создающий агрегированную диаграмму:
```js
```
m ? m + n : n
******

<a id="field-expressions"></a>
## Выражения полей

<a id="value-expressions"></a>
### Выражения значений

Выражения значений вычисляют значение поля на основе предоставленного выражения.
Выражение значения — это простое выражение, результатом которого является одно значение.
Если ваше поле является мультизначным, вам нужно вернуть массив элементов.

Обратитесь к [Expr](modules/integrator-guide/pages/compose-configuration/expr/index.md) за подробностями о написании выражений.

!!! important
    В настоящее время вы можете использовать только значения текущей записи.
    Ссылки пока не поддерживаются.
    Если вам нужно ссылаться на данные из нескольких записей, вместо этого используйте [автоматизацию](modules/integrator-guide/pages/compose-configuration/automation/index.md).


.Доступные переменные в контексте вычисления:
[cols="1s,5a"]
|===

| [#values-ctx-old]#[values-ctx-old,`old`](#values-ctx-old,`old`)#
|
Переменная `old` ссылается на исходную запись.
Задаётся только при обновлении поля.

| [#values-ctx-new]#[values-ctx-new,`new`](#values-ctx-new,`new`)#
|
Переменная `new` ссылается на текущую запись.

| [#values-ctx-value]#<<values-ctx-value,`<field-name>`>>#
|
Строка или массив строк с текущими значениями полей.
Если имя поля совпадает с какой-либо из системных переменных, обратитесь к значению через [values-ctx-new,new["field*name*here"]](#values-ctx-new,new["field*name*here"]).

|===

.Пример выражения, вычисляющего цену с налогом:
```
```
price * 1.25

.Пример выражения, формирующего полное имя:
```
```
trim(firstName + " " + lastName)

.Пример вычисления мультизначного выражения:
```
```
["foo", "bar", "baz"]

<a id="value-sanitizers"></a>
### Санатизаторы

Санатизаторы изменяют значение поля, чтобы очистить (санитизировать) данные перед сохранением.
Санатизатор — это простое выражение, результатом которого является одно значение.

!!! important
    Санатизаторы выполняются несколько раз: один раз перед отправкой данных в шину событий (corredor и рабочие процессы) и второй раз непосредственно перед отправкой записи в API.


Обратитесь к [Expr](modules/integrator-guide/pages/compose-configuration/expr/index.md) за подробностями о написании выражений.

По своей природе санатизаторы **не должны** приводить к ошибке.
Если ошибка возникает, она регистрируется в журнале действий, и операция продолжается.

Если вы определяете несколько санатизаторов, они выполняются в указанном порядке.

.Пример санатизатора, ограничивающего длину текста:
```
```
length(value) > 5 ? substr(value, 0, 5) + "..." : value

.Доступные переменные в контексте вычисления:
[cols="1s,5a"]
|===

| [#sanitizer-ctx-value]#[sanitizer-ctx-value,`value`](#sanitizer-ctx-value,`value`)#
|
Переменная `value` ссылается на текущее значение.

|===

<a id="value-validators"></a>
### Валидаторы

Валидаторы проверяют значение поля, вызывая ошибки, когда значение недействительно.
Валидатор — это простое выражение, результатом которого является одно значение: `true` или `false`.
Проверка значения считается недействительной, когда выражение возвращает `true`.

!!! important
    Валидаторы не могут изменять значение поля.


Встроенные валидаторы полей можно отключить; валидаторы обязательности и уникальности мультизначных значений отключить нельзя.

Если вы определяете несколько валидаторов, они выполняются в указанном порядке.

!!! important
    Валидатор поля останавливается при возникновении первой ошибки.
    Например, если мы определим валидаторы `A`, `B` и `C`, и валидатор `A` вызовет ошибку, валидаторы `B` и `C` не будут выполнены.


.Проверочные выражения не выполняются, когда:
- значение не изменено,
- значение отсутствует.

!!! tip
    Используйте флаг required для проверки обязательных значений.


.Доступные переменные в контексте вычисления:
[cols="1s,5a"]
|===

| [#validator-ctx-value]#[validator-ctx-value,`value`](#validator-ctx-value,`value`)#
|
Переменная `value` ссылается на текущее значение.

| [#validator-ctx-oldvalue]#[validator-ctx-oldvalue,`oldValue`](#validator-ctx-oldvalue,`oldValue`)#
|
Переменная `oldValue` ссылается на исходное значение.
Задаётся только при обновлении поля.

| [#validator-ctx-values]#[validator-ctx-values,`values`](#validator-ctx-values,`values`)#
|
Переменная `values` ссылается на все значения записи (`values.<field-name>`).
Вы можете использовать её для создания валидаторов, учитывающих контекст.

|===

.Пример валидатора для проверки длины текста:
```
```
length(title) < 5

## Обновление блоков страницы

Блоки страницы имеют опцию обновления для автоматического обновления своих данных без перезагрузки всей страницы; это полезно для блоков страницы, отображающих данные, которые часто меняются, например список новых лидов, обновление диаграммы или список последних комментариев.

!!! note
    Блоки автоматизации, файлов, содержимого и навигации не имеют опции обновления.
