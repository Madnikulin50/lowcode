# Доступ к LowCoooode

LowCoooode разделяет серверную бизнес-логику и клиентский пользовательский интерфейс, определяя API, к которому могут обращаться клиенты (веб-приложения и другие пользовательские приложения).

LowCoooode является API-центричным, что означает, что всё можно сделать через эндпоинт API.

<a id="authentication"></a>
## Аутентификация

LowCoooode использует токены Bearer JWT при аутентификации HTTP-запросов.

!!! warning
    Токены JWT предоставляют доступ к вашей системе, поэтому относитесь к ним как к учётным данным для входа.


### Получение токенов доступа

Прежде чем вы сможете получить токен доступа, вам нужно определить **клиента аутентификации** и **системного пользователя**.
Вы можете использовать существующего пользователя (например, себя) или создать отдельного пользователя.

!!! caution
    Убедитесь, что системный пользователь имеет достаточные роли для доступа к ресурсам, к которым вы хотите получить доступ.


Создайте нового клиента аутентификации с типом предоставления `client_credentials`.
Вставьте идентификатор выбранного пользователя в поле «Impersonate user» (это упомянутый выше пользователь).

!!! important
    Убедитесь, что вы используете LowCoooode [2021.3.4](modules/ROOT/pages/changelog/202103.md#p2021_3_4) или любые последующие версии.


Если идентификатор пользователя не задан или недействителен, возвращается ошибка `Error: "auth client security configuration invalid"`.

.Используйте следующий пример запроса cURL, чтобы получить токен доступа:
```bash
```
curl -X POST $LOWCODE_URL/auth/oauth2/token \
     -d grant*type=client*credentials \
     -d scope=api \
     -u <client id>:<client secret>

.Пример запроса cURL:
```bash
```
curl -X POST $LOWCODE_URL/auth/oauth2/token \
     -d grant*type=client*credentials \
     -d scope=api \
     -u 229978909641277628:sMVVcYpXE6bOUm6gG0sJGKmDOzEgkYyhvKyrmcU9fGY8M4GhLd90lThZDxUUFLC9

.Пример объекта ответа:
```json
```
{
  "access_token": "ey...MsLA",
  "expires_in": 7200,
  "refresh*token*expires_in": 0,
  "scope": "api",
  "sub": "229974909641277121",
  "token_type": "Bearer"
}

!!! caution
    Приведённый выше токен истекает через два часа; при необходимости обязательно получите новый.


### Использование токенов доступа

Каждый HTTP-запрос к **защищённому ресурсу** должен содержать токен Bearer JWT в заголовке `authorization`.

.Неавторизованные запросы возвращают ответ с ошибкой:
```json
```
{
  "error": {
    "message": "Unauthorized"
  }
}

.Пример cURL с аутентификацией:
```bash
```
curl "$LOWCODE_URL" \
  -H 'accept: application/json, text/plain, */*' \
  -H "authorization: Bearer $JWT";

.Пример cURL без аутентификации:
```bash
```
curl "$LOWCODE_URL" \
  -H 'accept: application/json, text/plain, */*';

<a id="api-endpoints"></a>
## Эндпоинты

Каждый инстанс LowCoooode поставляется со встроенной справкой по API, доступной по эндпоинту `/docs` вашего API LowCoooode.

!!! note
    Если вы используете *отдельный поддомен* для вашего API (два отдельных Docker-контейнера для веб-приложения и API), URL должен выглядеть примерно так: `https://api.$BASE_URL/docs`.
    
    Если вы используете *один и тот же домен* для вашего API (один Docker-контейнер для веб-приложения и API), URL должен выглядеть примерно так: `https://$BASE_URL/api/docs`.


Здесь рассматриваются эндпоинты, используемые для отладки и обслуживания.
Обратитесь ко встроенной справке по API для получения полного списка доступных эндпоинтов.

!!! tip
    Вы можете использовать справку по API https://latest.lowcode.org/api/docs/[community instance].


В дополнение к упомянутой выше справке по API существуют следующие системные эндпоинты, которые необходимо явно включить.
Их можно включать для разработки или отладки, но они должны быть отключены при работе в продакшене.

.Системные эндпоинты:
[cols="1m,5a"]
|===
| Опция | Эндпоинты

| HTTP*ENABLE*DEBUG_ROUTE
|
- `/__profiler` предоставляет данные профилирования времени выполнения сервера в формате, ожидаемом инструментом визуализации pprof.
- `/__routes` предоставляет список всех зарегистрированных маршрутов.
- `/__eventbus` представляет список всех зарегистрированных триггеров скриптов автоматизации.
- `/__corredor` представляет список всех зарегистрированных скриптов автоматизации.

| HTTP*ENABLE*VERSION_ROUTE
|
- `/version` показывает время сборки и версию LowCoooode.

| HTTP*ENABLE*HEALTHCHECK_ROUTE
|
- `/healthcheck` выполняет и отображает проверку работоспособности системы.

|===

<a id="response-format"></a>
## Формат данных ответа

LowCoooode реализует три различных формата ответа в зависимости от того, что вы пытаетесь сделать, и от статуса.

!!! important
    Ответы об ошибках используют код состояния 200 OK вместо стандартных 4xx/5xx — по причинам обратной совместимости.
    Наши API-клиенты обрабатывают этот случай и выбрасывают корректные ошибки.


.Различные форматы ответа:
[cols="2a,5a"]
|===
| [#response-single-items]#[response-single-items,Работа с одиночными элементами](#response-single-items,Работа с одиночными элементами)#
|

При работе с одиночными элементами сам элемент (или его статус) предоставляется в объекте ответа.

.Пример:
```json
```
{
  "response": {...}
}

| [#response-multiple-items]#[response-multiple-items,Работа с несколькими элементами](#response-multiple-items,Работа с несколькими элементами)#
|

При работе с несколькими элементами список элементов предоставляется в массиве ответа вместе с объектом фильтра.

.Пример:
```json
```
{
  "response": {
    "filter": {...},
    "set": [...]
  }
}

!!! note
    Структура свойства `filter` различается в зависимости от ресурса.
    В целом оно указывает, какие фильтры были применены к возвращаемому набору.


| [#response-errors]#[response-errors,Возникла ошибка](#response-errors,Возникла ошибка)#
|

При возникновении ошибки сообщение об ошибке предоставляется в свойстве `error.message`.

.Пример:
```json
```
{
  "error": {
    "message": "..."
  }
}

Когда вы включите трассировку ошибок через переменную окружения `HTTP*ERROR*TRACING`, дополнительные контексты ошибок предоставляются в свойствах `stack` и `wrap`.
Это может быть полезно для отладки, но в продакшене эту опцию следует отключить.

.Пример:
```json
```
{
  "error": {
    "message": "...",
    "stack": [...],
    "wrap": {...}
  }
}

|===
