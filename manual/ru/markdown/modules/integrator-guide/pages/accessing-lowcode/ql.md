# Язык запросов

LowCoooode реализует синтаксис, похожий на SQL, для запросов и сортировки записей.

## Запросы

.Общий шаблон для построения запроса выглядит так:
```
```
FIELD OPERATOR VALUE [AND|OR FIELD OPERATOR VALUE [...]]

******
- `[ ]` указывает, что заключённое содержимое является необязательным.
- `...` означает, что текущее заключённое содержимое повторяется.
******

Для следующих примеров предположим, что у нас есть модуль с именем `test` со следующими полями:

- `quantity` типа `Number`
- `price` типа `Number`
- `name` типа `String`
- `visible` типа `Checkbox`

.Чтобы запросить записи с нулевым количеством или нулевой ценой:
```
```
quantity = 0 or price = zero

.Чтобы запросить все видимые записи, начинающиеся с буквы «a»:
```
```
visible AND name LIKE 'a%'

### Операторы сравнения

Равно::
  - `=`
Не равно::
  - `!=`
  - `<>`
Меньше::
  - `<`
Меньше или равно::
 - `\<=`
Больше::
  - `>`
Больше или равно::
  - `>=`
Соответствует шаблону::
  - `LIKE`
Не соответствует шаблону::
  - `NOT LIKE`

При сопоставлении с шаблоном используйте `_` для представления одного символа; используйте `%` для представления нуля, одного или нескольких символов.

### Арифметические операторы

Сложение::
  - `+`
Вычитание::
  - `-`
Умножение::
  - `*`
Деление::
  - `/`

### Логические операторы

- `AND`: истинно, когда и левое, и правое истинны
- `OR`: истинно, когда левое или правое истинно

### Многозначные поля

Фильтры для многозначных полей выглядят точно так же, как и для обычных полей.

.Например; рассмотрим модуль со следующими полями:
- Имя поля: `users`, тип поля: `user selector`, отмечена опция мультизначения.
- Имя поля: `selects`, тип поля: `Select / dropdown`, отмечена опция мультизначения.

.В следующей таблице приведены примеры с соответствующим запросом и ожидаемым результатом:
[cols="2s,5m,5a"]
|===
| [#query-mv-example-1]#[query-mv-example-2,Фильтр по текущему пользователю](#query-mv-example-2,Фильтр по текущему пользователю)#
| users = $\{userID}
| Фильтр возвращает записи, где одно из многозначных значений соответствует текущему пользователю.

| [#query-mv-example-3]#[query-mv-example-4,Фильтр выбора по шаблону](#query-mv-example-4,Фильтр выбора по шаблону)#
| selects LIKE 'a%'
| Фильтр возвращает записи, где одна из многозначных опций выбора соответствует шаблону `a%`.

| Фильтр возвращает записи, где одна из многозначных опций выбора равна `a2`.

| Фильтр возвращает записи, где одна из многозначных опций выбора содержит `A`.

| Фильтр возвращает записи, где ни одна из многозначных опций выбора не содержит `A`.

## Сортировка

.Общий шаблон для построения сортировки выглядит так:
```
```
FIELD[ DIRECTION][, FIELD[ DIRECTION] [...]]

******
- `[ ]` указывает, что заключённое содержимое является необязательным.
- `...` означает, что текущее заключённое содержимое повторяется.
******

.Поддерживаемые направления:
- `ASC`: сортировка по возрастанию, сначала меньшие значения (значения `NULL` идут первыми).
Это сортировка по умолчанию, если `DIRECTION` не указан.
- `DESC`: сортировка по возрастанию, последними идут меньшие значения (значения `NULL` идут последними).

Для следующих примеров предположим, что у нас есть модуль с именем `test` со следующими полями:

- `quantity` типа `Number`
- `price` типа `Number`
- `name` типа `String`
- `visible` типа `Checkbox`

.Чтобы упорядочить записи по убыванию цены и возрастанию количества:
```
```
price DESC, quantity

### Многозначные поля

!!! important
    Сортировка по многозначным полям в настоящее время не поддерживается.
