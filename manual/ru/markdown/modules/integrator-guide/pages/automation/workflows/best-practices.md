# Рекомендации

## Задавайте столько ограничений триггера, сколько допускает здравый смысл

Когда вы нажимаете на иконку конфигурации {ICON*WORKFLOW*COG} в заголовке триггера, вы видите, что можно задать несколько ограничений триггера.

При определении «слабого триггера» вы можете столкнуться с ситуацией, когда некоторые события запускают рабочий процесс, хотя не должны.

Примером этого является модуль case в нашем CRM и в нашем Case Management.

.Определение триггера с такими ограничениями:
[annotation,role="data-zoomable"]
{
  "image": {
    "rel": "automation/workflows/best-practices/constraints-no.png",
    "alias": "automation-workflows-best-practices-constraints-no.png",
    "w": 1920,
    "h": 1080
  },
  "view": {},
  "annotations": []
}

Если обращение было создано в CRM или в Case Management, это всё равно приводит к выполнению рабочего процесса.

Чтобы исправить этот крайний случай, вы можете задать дополнительное ограничение, проверяющее пространство имён.
См. пример ниже.

[annotation,role="data-zoomable"]
{
  "image": {
    "rel": "automation/workflows/best-practices/constraints-yes.png",
    "alias": "automation-workflows-best-practices-constraints-yes.png",
    "w": 1920,
    "h": 1080
  },
  "view": {},
  "annotations": []
}

## Один шаг выражения может содержать несколько выражений

Когда вы нажимаете на иконку конфигурации {ICON*WORKFLOW*COG} в заголовке шага выражения, вы видите, что можно добавить несколько выражений.

Используйте это, чтобы сократить количество шагов выражений, но не переусердствуйте.
Если вы хотите изменить значения записи контакта и контрагента, определите только два шага выражения, где каждый фокусируется только на одной записи.

.Пример избыточно усложнённого рабочего процесса:
[annotation,role="data-zoomable"]
{
  "image": {
    "rel": "automation/workflows/best-practices/compact-no.png",
    "alias": "automation-workflows-best-practices-compact-no.png",
    "w": 1920,
    "h": 1080
  },
  "view": {
    "x": 121,
    "y": 121,
    "w": 936,
    "h": 610
  },
    "annotations": []
}

Приведённое выше легко переписать в форму ниже.

.Подходящий пример рабочего процесса:

## Большинство итераторов умеют загружать и обрабатывать данные

[Итераторы элементов](modules/integrator-guide/pages/automation/workflows/automation/workflows/index.md#iterator-kind-item), работающие с системными ресурсами (например, записи Low Code LowCoooode, системные пользователи и роли), могут и получать, и обрабатывать данные.

Когда вам нужно выполнить итерацию по внешним ресурсам (например, постам в социальных сетях), их нужно предварительно получить.

## Используйте handle, когда это возможно

Большинство ресурсов позволяют определить удобочитаемый идентификатор рядом с системно генерируемым идентификатором (handle, или слаг в случае пространства имён).

Эти идентификаторы упрощают написание рабочих процессов, работающих в разных инстансах, где идентификатор может быть не одинаковым.
Согласованность также повышается; проще читать `lead` как идентификатор модуля лидов, чем `12897612987021`.
