# Под-рабочие процессы
:attachment-path: ../../../_attachments/automation/workflows/scaling/

Под-рабочие процессы позволяют определять переиспользуемые фрагменты логики, которые могут использовать другие рабочие процессы.
Под-рабочий процесс можно представить как функцию в классических языках программирования.

!!! tip
    В списке доступных рабочих процессов есть дополнительный фильтр включения под-рабочих процессов.

<a id="exec-args"></a>
## Аргументы выполнения

При вызове под-рабочих процессов можно передать произвольный аргумент выполнения, закодированный как тип данных `Vars`.

Нажмите на значок шестерёнки {ICON*WORKFLOW*COG} на шаге exec-workflow {ICON*WORKFLOW*EXEC_WORKFLOW} и найдите раздел «arguments» (аргументы).
Любое значение, переданное в аргументе `scope`, будет доступно в контексте выполнения под-рабочего процесса.

<a id="exec-results"></a>
## Результаты выполнения

После завершения выполнения под-рабочего процесса вызывающий рабочий процесс получает доступ к области видимости под-рабочего процесса в том состоянии, в котором она была на момент завершения.

Нажмите на значок шестерёнки {ICON*WORKFLOW*COG} на шаге exec-workflow {ICON*WORKFLOW*EXEC_WORKFLOW} и найдите раздел «results» (результаты).
Укажите список значений (и имена переменных), которые вы хотите сохранить из под-рабочего процесса.
Поле `result` определяет имя переменной в состоянии под-рабочего процесса, а `target` — имя переменной в состоянии вызывающего.

!!! tip
    Количество значений, к которым можно получить доступ из состояния под-рабочего процесса, не ограничено.

## Создание под-рабочих процессов

Чтобы создать под-рабочий процесс, перейдите в веб-приложение Workflow и создайте новый рабочий процесс.
Отметьте флажок btn:[subworkflow] при настройке метаданных рабочего процесса.

Подробности см. в [основной документации по рабочим процессам](modules/integrator-guide/pages/automation/workflows/scaling/automation/workflows/index.md).

## Использование под-рабочих процессов

Под-рабочие процессы вызываются из *обычных* рабочих процессов с помощью шага **exec-workflow** {ICON*WORKFLOW*EXEC_WORKFLOW}.
Шаг **exec-workflow** {ICON*WORKFLOW*EXEC_WORKFLOW} требует указать, какой рабочий процесс вы хотите выполнить (это должен быть под-рабочий процесс), [exec-args,аргументы выполнения](#exec-args,аргументы выполнения) и [exec-results,результаты выполнения](#exec-results,результаты выполнения).
