# Развёртывание скриптов автоматизации

!!! note
    *DevNote*: обобщить и не ограничиваться только скриптами автоматизации.


Чтобы использовать скрипты автоматизации, необходимо сделать их доступными серверу Corredor — либо локально, либо на сервере.

!!! important
    При запуске *Corredor без Docker* (из исходного кода) можно пропустить любые *шаги, связанные с Docker*.


.Мы предполагаем, что:
- ваш **текущий рабочий каталог** — это место, где находится ваше расширение,
- ваш **LowCoooode расположен внутри** `/opt/deploy/test-project`,
- **структура файлов** `/opt/deploy/test-project` выглядит так:

```txt
```
data/
docker-compose.yml
.env

.Чтобы развернуть скрипты автоматизации:
1. Создайте новый каталог для вашего расширения; мы назовём его `corredor`, но имя не имеет значения.
1. **Перенесите расширение** в только что созданный каталог (см. разделы ниже с советами).
1. Добавьте **новый том** в файл `docker-compose.yaml`, который **содержит расширение**, в сервисе `corredor`, `volumes: [ "./corredor:/corredor/test-extension", ...другие ваши тома... ]`.
1. Отредактируйте файл `.env` (переменная `CORREDOR*EXT*SEARCH*PATHS`), чтобы **зарегистрировать новое расширение** `CORREDOR*EXT*SEARCH*PATHS=/extensions:/extensions/*:/corredor/test-extension`.
1. **Перезагрузите конфигурации** (`docker-compose up -d`).

.В итоге ваша структура файлов должна выглядеть следующим образом:
```txt
```
data/
docker-compose.yml
.env
corredor/
  test-extension/
    server-scripts/
      /...
    client-scripts/
      /...

!!! important
    `CORREDOR_EXT_SEARCH_PATHS` может содержать несколько путей, разделённых двоеточием (`:`).


!!! tip
    Вы можете использовать `docker-compose logs -t --tail 100 -f corredor`, чтобы проверить, было ли расширение зарегистрировано и обработано корректно.


## Перенос расширений с помощью git

Если вы используете Git для управления версиями вашего расширения, **клонируйте** репозиторий на свой сервер (в том, что упоминался выше).
Затем вы можете **получать изменения** всякий раз, когда изменяется исходный код.

!!! note
    Если репозиторий *приватный*, убедитесь, что Git-клиент на вашем сервере имеет к нему доступ.


## Ручной перенос расширений

Вы можете использовать `scp`, `rsync` или любой другой клиент для переноса расширения на свой сервер (в упомянутый ранее том).

!!! note
    Обычно мы используем `rsync`, так как он несколько лучше определяет изменения файлов.


.Вот пример команды `rsync` **с учётом приведённых выше допущений**.
```bash
```
rsync -av -e ssh --exclude="node*modules/**" ./** SSH*USERNAME_HERE@ssh.remote.tld:/opt/deploy/test-project/corredor --delete;

Перед выполнением приведённой выше команды обязательно **измените параметры**.
