# Node-модули

!!! important
    Разные расширения *не разделяют* свои зависимости.
    Если два расширения используют *одну и ту же зависимость*, оба должны *определить её*.


LowCoooode Corredor поддерживает внутренние и внешние node-модули как в server-scripts, так и в client-scripts.

!!! note
    Внутри мы используем пакетный менеджер Yarn.
    Мы рекомендуем вам делать то же самое.


.Чтобы добавить новый node-модуль, либо:
- вставьте его вручную в файл `package.json`, или
- выполните `yarn add NAME*GOES*HERE`.

При запуске сервер Corredor пытается автоматически разрешить и установить запрошенные зависимости.

!!! caution
    Мы наблюдаем некоторые аномалии при запуске *Yarn внутри docker-контейнера*.
    
    Если вы получаете сообщение об ошибке, похожее на приведённое ниже, это означает, что Yarn не может *установить зависимости*.
    Эта ошибка возникает, когда Yarn не может сохранить свой кэш.
    
    ****
    {
      "type": "error",
      "data": "https://registry.yarnpkg.com/rxjs/-/rxjs-6.6.3.tgz: Extracting tar content of undefined failed, the file appears to be corrupt: \\"ENOSPC: no space left on device, write\\""
    }
    ****
    
    .Чтобы устранить аномалию, необходимо:
    . Подключиться по SSH *к контейнеру Corredor* (`docker-compose exec -u root corredor sh`),
    . `cd` *в смонтированный том*,
    . выполнить *`yarn --cache-folder /tmp`*.
    
    Теперь зависимости должны быть *установлены и доступны* для использования.
    Приведённая выше команда `yarn` *вручную запускает процесс установки*, *отбрасывая кэш*.


После этого node-модули можно использовать **точно так же, как и в любой другой ситуации**.

.Пример package.json:
```json
```
{
  "dependencies": {
    "axios": "^0.18.0"
  }
}

.Пример использования из скриптов автоматизации:
```js
```
import axios from 'axios'

export default {

  async exec() {
    await axios.get(...)

  }
}
