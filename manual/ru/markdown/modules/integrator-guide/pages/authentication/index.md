# Аутентификация

LowCoooode реализует протокол аутентификации OAuth2, где он может выступать как сервер OAuth2, так и клиент OAuth2, что позволяет выполнять как внутреннюю, так и внешнюю аутентификацию.

Базовые параметры аутентификации настраиваются в веб-приложении LowCoooode Admin в разделе menu:system[settings] в секции «аутентификация».

## Определение требований к паролю

LowCoooode позволяет вам задавать собственные требования к паролям.
Это позволяет лучше соответствовать вашей модели безопасности.

Требования к паролям настраиваются в веб-приложении LowCoooode Admin в разделе menu:system[settings] в секции «Требования к паролям».

[cols="2s,5a"]
|===
| [#auth-password-constraint-len]#[auth-password-constraint-len,Минимальная длина](#auth-password-constraint-len,Минимальная длина)#
|
Параметр минимальной длины позволяет ограничить использование пользователями коротких, небезопасных паролей.
Минимальную длину нельзя установить ниже 8 символов.

Максимальная длина пароля не настраивается и составляет 256 символов.

| [#auth-password-constraint-numbers]#[auth-password-constraint-numbers,Минимальное количество цифр](#auth-password-constraint-numbers,Минимальное количество цифр)#
|
Минимальное количество цифр позволяет требовать от пользователей использования числовых символов в паролях.
Требование отключается, когда значение оставлено равным 0.

| [#auth-password-constraint-symbols]#[auth-password-constraint-symbols,Минимальное количество специальных символов](#auth-password-constraint-symbols,Минимальное количество специальных символов)#
|
Минимальное количество специальных символов позволяет требовать от пользователей использования специальных символов в паролях.
Требование отключается, когда значение оставлено равным 0.

|===

!!! caution
    Переменная `AUTH_PASSWORD_SECURITY` в `.env` позволяет отключить проверку требований к паролю, установив её в `false`.
    Это удобно для локальной разработки, где вы можете не захотеть иметь дело со сложными требованиями к паролям.
    
    Для любого продакшн-развёртывания эта опция должна быть *отключена*.
    Если безопасность пароля отключена, в интерфейсе отображается предупреждающее сообщение.

## Клиент аутентификации

**Клиент аутентификации** обеспечивает контроль доступа высокого уровня к использованию API LowCoooode и его ресурсов.
Клиент аутентификации — это то, что используют приложения, когда их пользователи пытаются пройти аутентификацию.

!!! tip
    Вы можете использовать LowCoooode для аутентификации сторонних приложений, поддерживающих OAuth2/OIDC.


Клиенты аутентификации можно определить в панели LowCoooode Admin, в разделе menu:system[auth clients].

.Оттуда вы можете:
- просматривать список клиентов аутентификации, созданных в вашем инстансе LowCoooode,
- создать новый клиент аутентификации, нажав кнопку btn:[new],
- редактировать существующий клиент аутентификации, нажав на значок btn:[edit] рядом с клиентом аутентификации,
- управлять глобальными разрешениями клиента аутентификации, нажав кнопку btn:[permissions].

### Типы предоставления

LowCoooode поддерживает два типа предоставления OAuth2: **код авторизации** и **учётные данные клиента**.

.Типы предоставления аутентификации:
[cols="1s,5a"]
|===
| [#auth-client-grant-authorization-code]#[auth-client-grant-authorization-code,Код авторизации](#auth-client-grant-authorization-code,Код авторизации)#
|
Тип предоставления **код авторизации** используется для аутентификации пользователей по классическому потоку OAuth2.

Чтобы включить этот тип предоставления, выберите опцию «будет использоваться для аутентификации пользователей (grant type = authorization_code)».

|
Тип предоставления **учётные данные клиента** — это упрощённый поток аутентификации.
Обычно он используется для аутентификации систем, таких как внешние сервисы или приложения.

!!! important
    Тип предоставления «учётные данные клиента» требует заполнить опцию «выступить от имени пользователя».
    Пользователь, от имени которого выполняется вход, будет использован для создания контекста безопасности JWT-токена.


Чтобы включить этот тип предоставления, выберите опцию «будет использоваться для аутентификации машин (grant type = client_credentials)».

### Область авторизации

Область доступа определяется как набор членств в ролях, которые **разрешены**, **запрещены** или **принудительно назначены** пользователю при использовании конкретного сервера аутентификации LowCoooode.

|===
| [#auth-scope-permitted]#[auth-scope-permitted,Разрешённые роли](#auth-scope-permitted,Разрешённые роли)#
| **Разрешённые роли** определяют, какие роли пользователю **разрешено иметь** при аутентификации с этим клиентом.

| [#auth-scope-prohibited]#[auth-scope-prohibited,Запрещённые роли](#auth-scope-prohibited,Запрещённые роли)#
| **Запрещённые роли** определяют, какие роли пользователю **не разрешено иметь** при аутентификации с этим клиентом.

| [#auth-scope-forced]#[auth-scope-forced,Принудительные роли](#auth-scope-forced,Принудительные роли)#
| **Принудительные роли** определяют, какие роли пользователь **будет иметь** при аутентификации с этим клиентом.
Если у пользователя нет принудительной роли, ему будет автоматически назначена роль.
|===

## Ограничение доступа

По умолчанию любой пользователь может использовать любой клиент аутентификации.
Чтобы ограничить доступ к конкретным клиентам аутентификации, перейдите к клиенту аутентификации и установите правило контроля доступа «авторизовать клиент».

Если у конкретной роли нет правила RBAC «авторизовать клиент», входящие в неё пользователи не смогут пройти аутентификацию с данным клиентом аутентификации.
