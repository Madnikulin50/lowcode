# Аутентификация внешних приложений

LowCoooode реализует протокол аутентификации OAuth2, где он может выступать как сервер OAuth2, так и клиент OAuth2, что позволяет выполнять как внутреннюю, так и внешнюю аутентификацию.

Вы можете разрешить внешним приложениям использовать LowCoooode в качестве поставщика аутентификации, если они поддерживают аутентификацию по протоколам OAuth2/OIDC.

После успешной авторизации с использованием локальных учётных данных или внешнего поставщика выдаются **токен доступа** и **токен обновления**.
Это должно выполняться автоматически клиентом.

Токен доступа является короткоживущим и должен автоматически обновляться — токен доступа действует **2 часа**, а токен обновления действует **3 дня**.
Вы можете управлять сроком действия токенов с помощью переменных `.env` `AUTH*OAUTH2*ACCESS*TOKEN*LIFETIME` и `AUTH*OAUTH2*REFRESH*TOKEN*LIFETIME`.
Подробнее см. [определение длительности сессии](modules/integrator-guide/pages/authentication/authenticate-external/authentication/session-duration.md).

!!! tip
    Вы можете использовать наши https://github.com/lowcode/lowcode-vue/blob/2022.9.x/src/plugins/auth.ts[lowcode-vue plugins/auth] для управления этим за вас.


## Конфигурация LowCoooode

Откройте панель LowCoooode Admin и перейдите в menu:system[auth clients].
Создайте новый клиент аутентификации, который ваше внешнее приложение будет использовать для аутентификации.

!!! important
    Мы советуем создавать отдельный клиент аутентификации для каждого приложения, которое вы хотите интегрировать.
    Повторное использование одного и того же клиента может предоставить некоторым интеграциям права доступа, которых у них быть не должно.


.Клиент аутентификации состоит из:
1. комбинации идентификатора клиента и секрета клиента (идентификатор клиента находится в адресной строке URL),
1. списка областей доступа для ограничения доступа на основе используемого клиента аутентификации,
1. списка URI перенаправления, которые можно использовать с кодом авторизации,
1. доверенного флага, чтобы заставить пользователей подтверждать аутентификацию,
1. срока действия клиента аутентификации на основе даты.

!!! important
    Убедитесь, что вы выбрали подходящий тип предоставления для вашего сценария использования.
    Подробнее см. [здесь](modules/integrator-guide/pages/authentication/authenticate-external/authentication/index.md#grant-types).

## Жизненный цикл аутентификации

!!! note
    *DevNote* todo; expand on this section.


Сессия на сервере аутентификации LowCoooode отличается от сессии в клиентском приложении.
Это разделение позволяет использовать сессию аутентификации LowCoooode при авторизации дополнительных клиентов.

!!! caution
    Поскольку сессии аутентификации между разными клиентами различаются, каждая сессия должна быть отозвана, чтобы пользователь действительно был выведен из системы.


## Заметки о безопасности

- Используйте HTTPS с действующими SSL-сертификатами.
- Формы и эндпоинты аутентификации защищены от атак перебором и межсайтовых запросов.
Вы также можете задать собственные секреты для шифрования JWT, CSRF и cookie-значений.
- Для временных и постоянных сессий могут быть установлены разные сроки действия, соответствующие политике безопасности вашей организации.
- См. [полный список опций](modules/devops-guide/pages/references/configuration/server.md#_authentication).
Эти изменения вступают в силу после перезапуска сервера.

!!! note
    Если какой-либо из секретов изменён, пользователи получат различные предупреждения и будут выведены из системы.


## Советы по отладке

.Если ваше внешнее приложение не может пройти аутентификацию, проверьте следующее:
- идентификатор и секрет клиента должны совпадать,
- по крайней мере один из URI перенаправления клиента должен совпадать (по префиксу),
- поток предоставления клиента должен совпадать,
- область доступа клиента должна совпадать (запрошенная группа областей доступа должна пересекаться с областями доступа клиента),
- пользователь, авторизующий клиента, должен быть носителем роли, которая может авторизовать клиента,
- пользователь должен быть действительным (подтверждённая почта, не заблокирован, не удалён).
