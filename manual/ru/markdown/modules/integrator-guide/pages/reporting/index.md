# Отчёты

LowCoooode Reporter позволяет создавать красивые отчёты, используя данные, хранящиеся в ваших приложениях Low Code.
Этот раздел посвящен наиболее важным аспектам системы. Если вы хотите узнать больше о конкретной теме, обратитесь к подразделам в меню menu:Low-Code Platform Developer Guide[Reporting].

## Создание нового отчёта

Чтобы создать отчёт, перейдите в ваш экземпляр LowCoooode (например http://latest.lowcode.org/) и нажмите на приложение "Reporter".

![role="data-zoomable"](reporter/app-selector.png)

Появится новый экран, показывающий все доступные отчёты.

.Оттуда вы можете:
- создавать новые отчёты, нажав на кнопку btn:[New Report],
- редактировать существующие отчёты, нажав на кнопку btn:[edit],
- открыть конструктор отчётов, нажав на кнопку btn:[Report builder],
- управлять глобальными разрешениями, нажав на кнопку btn:[Permissions],
- управлять разрешениями для конкретного отчёта, нажав на иконку "Lock" рядом с отчётом.

![role="data-zoomable"](reporter/report-list.png)

Когда вы нажимаете на кнопку btn:[New report], появляется новый экран с предложением указать базовые параметры отчёта.

- **Name** предоставляет удобный для пользователя идентификатор отчёта; например "Test Report".
Имя не накладывает никаких особых ограничений.
- **Handle** определяет [report-handle-constraints,уникальное значение](#report-handle-constraints,уникальное значение), которое может использоваться вместо системного идентификатора для более простой ссылки.
- **Description** определяет подробное описание отчёта, чтобы лучше объяснить, что показывает отчёт.
- **Tags** определяют серию коротких текстовых фрагментов для описания вашего отчёта.

<a id="report-handle-constraints"></a>
.Ограничения handle:
1. начинаться с символа,
1. содержать не более 64 символов,
1. содержать только символы, цифры, _ (подчёркивание), - (дефис) или . (точка),
1. заканчиваться символом или цифрой.


![role="data-zoomable"](reporter/report-create.png)

## Конструктор отчётов

Конструктор отчётов используется для определения структуры отчётов с помощью **блоков отчёта** и интерфейса перетаскивания.
Каждый отчёт имеет сетку из 12 колонок и не ограничен по вертикальной оси.

![role="data-zoomable"](reporter/report-builder-base.png)

Нажмите на кнопку btn:[+ Add block], чтобы добавить новый блок отчёта, который может содержать дополнительные источники данных и элементы отображения.

![role="data-zoomable"](reporter/report-builder-block-base.png)

Чтобы получить доступ к общим параметрам конфигурации блока отчёта (заголовок, описание и направление макета), нажмите на иконку "edit" в левом нижнем углу блока отчёта.

![role="data-zoomable"](reporter/report-builder-block-config.png)

Элементы отображения могут быть доступны, добавлены, отредактированы и удалены, перейдя на вкладку "elements" модального окна общей конфигурации блока отчёта.

![role="data-zoomable"](reporter/report-builder-block-el.png)

Элементы отображения можно быстро добавить, нажав на иконку "add" в левом нижнем углу блока отчёта.

![role="data-zoomable"](reporter/report-builder-elements.png)

Чтобы переместить блок отчёта, просто перетащите его в нужное位置.

Блок отчёта может быть размещен в любом месте по оси X, но его ось Y должна соединяться с другим блоком отчёта или с верхней частью страницы.
Если позиция недопустима или блок накладывается на другой блок отчёта, конструктор отчётов может автоматически скорректировать окружающие блоки отчёта для соблюдения ограничений.

![width=49%](reporter/report-builder-repos-base.png)
![width=49%](reporter/report-builder-repos.png)

Чтобы изменить размер блока отчёта, просто возьмитесь за стрелку в правом нижнем углу и измените размер по своему усмотрению.
Блок отчёта не может превышать максимальную ширину в 12 колонок.
Высота не ограничена.

![width=49%](reporter/report-builder-resize-base.png)
![width=49%](reporter/report-builder-resize.png)

Чтобы удалить блок отчёта, нажмите на иконку "trash can" в левом нижнем углу блока отчёта и подтвердите действие, нажав на кнопку подтверждения.

![role="data-zoomable"](reporter/report-builder-delete.png)

## Источники данных

!!! note
    *DevNote* ссылка на дополнительные примеры.


Источник данных определяет, к какому ресурсу осуществляется доступ, как данные предварительно обрабатываются и представляются в отчёт.
Большинство источников данных могут быть использованы как входные данные для другого источника данных.

!!! important
    Источник данных должен определять имя, уникальное среди других источников данных, определенных текущим отчётом и любыми его блоками.


Мы можем определять источники данных на двух уровнях: для всего отчёта и для конкретного блока отчёта.

При определении источников данных для всего отчёта любые блоки и их элементы должны иметь доступ к данным, предоставленным источником данных.
Такой источник данных следует использовать, когда мы хотим определить некоторые предварительно вычисленные данные, которые будут использоваться во всём отчёте.
Источники данных уровня отчёта доступны по нажатию на кнопку btn:[Data sources] в правом верхнем углу [report-builder,конструктора отчётов](#report-builder,конструктора отчётов).

При определении источников данных для конкретных блоков отчёта только элементы внутри данного блока отчёта могут получить доступ к данным, предоставленным источником данных.
Такой источник данных следует использовать, когда вы хотите дополнительно преобразовать некоторые предварительно вычисленные данные, предоставленные источниками данных уровня отчёта.
Источники данных уровня блока доступны по нажатию на иконку "edit" определенного блока и переходу в раздел "data sources".

### Load

Источник данных load позволяет обращаться к ресурсам непосредственно из LowCoooode, таким как ваши лиды CRM.
Ресурсы могут быть предварительно отфильтрованы и предварительно отсортированы, что позволяет показывать данные на основе определенной характеристики, например временного промежутка.

Source определяет, какой ресурс LowCoooode предоставляет данные; например "compose records".

.Пример показывает конфигурацию источника данных load.
![role="data-zoomable"](reporter/load.png)

.Параметры конфигурации источника Compose record:
[cols="1s,5a"]
|===
| [#ds-load-records-namespace]#[ds-load-records-namespace,Namespace](#ds-load-records-namespace,Namespace)#
|
Namespace определяет, к какому пространству имен Low Code осуществляется доступ; например "CRM" или "Case Management".

| [#ds-load-records-module]#[ds-load-records-module,Module](#ds-load-records-module,Module)#
|
Module определяет, к какому модулю осуществляется доступ; например "lead" или "contact".

| [#ds-load-records-prefilter]#[ds-load-records-prefilter,Pre-filter](#ds-load-records-prefilter,Pre-filter)#
|
Pre-filter определяет, какая фильтрация должна быть применена к данным перед тем, как источник данных вернет данные.
Предварительная фильтрация позволяет показывать данные на основе указанной характеристики, такой как текущий квартал или лиды с определенным статусом.

Обратитесь к [предварительной фильтрации](modules/integrator-guide/pages/reporting/reporting/prefilter.md) для получения более подробной информации.

| [#ds-load-records-presort]#[ds-load-records-presort,Pre-sort order](#ds-load-records-presort,Pre-sort order)#
|
Pre-sort определяет, как результирующие данные должны быть отсортированы перед тем, как источник данных вернет их.
Это позволяет вам определить некоторый начальный порядок, например, сначала новые лиды или сначала самые старые клиенты.

Обратитесь к [предварительной сортировке](modules/integrator-guide/pages/reporting/reporting/presort.md) для получения более подробной информации.

### Group

Источник данных group позволяет агрегировать и преобразовывать данные, предоставленные другим источником данных, например, вычислять общую стоимость привлечения лидов или подсчитывать количество заданий, которые запросил клиент.

Source определяет, какой источник данных должен быть агрегирован, и он должен быть одним из предопределенных источников данных, таких как load или другой group.

.Пример показывает конфигурацию источника данных group.
![](reporter/group.png)

.Параметры конфигурации источника данных group:
[cols="1s,5a"]
|===
| [#ds-group-group-by]#[ds-group-group-by,Group by](#ds-group-group-by,Group by)#
|
Раздел group by определяет колонки, которые обозначают группы.
Например, определение выражения `AccountSource` для модуля CRM счетов группирует записи на основе источника счета.

Колонка группировки должна определять имя и необязательную метку и может быть использована другими источниками данных.

Обратитесь к [справочнику по выражениям](modules/integrator-guide/pages/reporting/reporting/expr-reference.md) для получения более подробной информации.

!!! important
    Группа должна определять как минимум 1 колонку группировки.


| [#ds-group-aggregate]#[ds-group-aggregate,Aggregate](#ds-group-aggregate,Aggregate)#
|
Раздел aggregate позволяет определить, как вычисляемые колонки будут оцениваться.
Например, определение выражения `count()` возвращает количество строк для каждой группы.

Колонка агрегации должна определять имя и необязательную метку и может быть использована другими источниками данных.

Обратитесь к [справочнику по выражениям](modules/integrator-guide/pages/reporting/reporting/expr-reference.md) для получения более подробной информации.

### Join

Источник данных join позволяет объединить два источника данных на основе общего значения, например, ссылки с использованием полей модуля `Record` или общей колонки статуса.

!!! caution
    Текущие версии не позволяют использовать источник данных join как входные данные для других источников данных.


!!! caution
    Любая строка из первичного источника, которая не имеет связанного вторичного источника, исключается из результата.
    Анти-соединения не поддерживаются.


.Пример показывает конфигурацию источника данных join.
![](reporter/join.png)

.Параметры конфигурации источника данных join:
[cols="1s,5a"]
|===
| [#ds-join-primary-source]#[ds-join-primary-source,Primary source](#ds-join-primary-source,Primary source)#
|
Первичный источник определяет базовый источник данных, участвующий в соединении, например, счет в отношении счет-контакт.

| [#ds-join-primary-column]#[ds-join-primary-column,Primary column](#ds-join-primary-column,Primary column)#
|
Первичная колонка определяет, какая колонка из [ds-join-primary-source,первичного источника](#ds-join-primary-source,первичного источника) должна использоваться при определении того, связаны ли две строки.

| [#ds-join-secondary-source]#[ds-join-secondary-source,Secondary source](#ds-join-secondary-source,Secondary source)#
|
Вторичный источник определяет источник данных, который мы хотим присоединить к первичному источнику, например, контакт в отношении счет-контакт.

| [#ds-join-secondary-column]#[ds-join-secondary-column,secondary column](#ds-join-secondary-column,secondary column)#
|
Вторичная колонка определяет, какая колонка из [ds-join-secondary-source,вторичного источника](#ds-join-secondary-source,вторичного источника) должна использоваться при определении того, связаны ли две строки.

## Элементы отображения

Элементы отображения позволяют получать доступ и отображать данные, предоставленные [источником данных](modules/integrator-guide/pages/reporting/reporting/index.md#datasources).
Элементы отображения могут существовать только внутри блока.
Один блок может определять несколько элементов отображения.

!!! tip
    Вы можете использовать <<el-table,таблицу>> и <<el-chart,диаграмму>> рядом, чтобы показать, какие данные были использованы для генерации визуализации.


Большинство элементов отображения могут определять дополнительную [предварительную фильтрацию](modules/integrator-guide/pages/reporting/reporting/prefilter.md) и [предварительную сортировку](modules/integrator-guide/pages/reporting/reporting/presort.md).

<a id="el-text"></a>
### Text

Элемент отображения text позволяет предоставлять произвольное содержимое, которое может использоваться вместе с другими элементами отображения, предоставляя дополнительный контекст данным.

Элемент отображения поддерживает форматированный текст с помощью [WYSIWYG](https://en.wikipedia.org/wiki/WYSIWYG) редактора.

### Metric

Элемент отображения metric позволяет отображать вычисленное числовое значение из предоставленного источника данных.

Вычисленное значение обычно является важным показателем для вашего процесса, таким как общая сумма финансов в вашей воронке продаж или текущее количество открытых счетов.

.Пример показывает настроенный элемент отображения metric.
![](reporter/metric-configuration.png)

.Параметры конфигурации элемента отображения metric:
[cols="1s,5a"]
|===
| [#el-metric-label]#[el-metric-label,Label](#el-metric-label,Label)#
|
Колонка метки определяет, какая колонка из источника данных используется при отображении метрики.
Колонка должна быть числовым значением.

| [#el-metric-format]#[el-metric-format,Format](#el-metric-format,Format)#
|
Определяет строку форматирования, которая используется при отображении метрики.
Поле поддерживает все опции форматирования [numeral.js](https://numeraljs.com/#format).

Формат применяется до префикса и суффикса.

| [#el-metric-pfx]#[el-metric-pfx,Prefix](#el-metric-pfx,Prefix)#
|
Определяет префикс, который добавляется перед результирующей метрикой перед ее отображением в блоке страницы.
Например, префикс `$` и значение `1000` приведут к метке `$1000`.

| [#el-metric-sfx]#[el-metric-sfx,Suffix](#el-metric-sfx,Suffix)#
|
Определяет суффикс, который добавляется к результирующей метрике перед ее отображением в блоке страницы.
Например, суффикс `USD/h` и значение `1000` приведут к метке `1000USD/h`.

| [#el-metric-color]#[el-metric-color,Text color](#el-metric-color,Text color)#
|
Определяет цвет текста отображаемой метки.

| [#el-metric-background]#[el-metric-background,Background color](#el-metric-background,Background color)#
|
Определяет цвет фона отображаемой метки.

### Chart

Элемент отображения chart позволяет визуализировать источник данных с помощью диаграммы.

!!! note
    Если вы работаете с [объединенным источником данных](modules/integrator-guide/pages/reporting/reporting/index.md#datasource-join), вы должны выбрать колонки для каждого объединенного источника данных.


.Поддерживаемые типы диаграмм:
- Bar
- Line
- Pie
- Doughnut
- Funnel

!!! important
    Диаграммы-воронки поддерживаются только при отображении [источника данных group](modules/integrator-guide/pages/reporting/reporting/index.md#datasource-group).


.Пример показывает настроенный элемент отображения chart.
![](reporter/chart-configuration.png)

.Параметры конфигурации элемента отображения chart:
[cols="1s,5a"]
|===
| [#el-chart-type]#[el-chart-type,Type](#el-chart-type,Type)#
|
Определяет, какая диаграмма из поддерживаемого списка должна использоваться.

| [#el-chart-scheme]#[el-chart-scheme,Color scheme](#el-chart-scheme,Color scheme)#
|
Цветовая схема определяет, какие цвета должна использовать ваша диаграмма при визуализации данных.

Имейте в виду, что каждая цветовая схема определяет ограниченное количество цветов, поэтому ваш выбор должен основываться на данных, которые вы пытаетесь показать.

Столбчатые и линейные диаграммы используют разные цвета для каждой колонки, в то время как другие диаграммы используют разные цвета для каждого значения.

| [#el-chart-label]#[el-chart-label,Label column](#el-chart-label,Label column)#
#
Колонка метки определяет, какие значения из источника данных используются в качестве метки для каждой точки данных диаграммы (легенды).

Для колонки метки могут быть выбраны только текстовые колонки.

| [#el-chart-data]#[el-chart-data,Data column](#el-chart-data,Data column)#
|
Колонки данных определяют, какие значения из источника данных используются в качестве точек данных диаграммы.

Для колонки данных могут быть выбраны только числовые колонки.
