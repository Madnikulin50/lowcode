# Expressions

LowCoooode определяет язык выражений, который используется при определении [выражений полей](modules/integrator-guide/pages/expr/compose-configuration/index.md#field-expressions), [шагов рабочих процессов](modules/integrator-guide/pages/expr/automation/workflows/index.md), а также [контекстных ролей](modules/integrator-guide/pages/expr/security-model/index.md#role-type-ctx).

!!! note
    Мы используем https://github.com/PaesslerAG/gval[Gval] в качестве движка вычисления выражений.
    Обратитесь к официальной документации за техническими подробностями.


## Syntax

.Самая базовая форма выражения выглядит следующим образом:
```
```
<variable|constant|function> <operator> <variable|constant|function>

!!! note
    В дальнейшем тексте мы обозначаем вышеуказанную строку и её вариации как `expression`.


.Пример:
```
```
lead.values.totalCost / 10

Вы можете расширить выражение, применяя дополнительные конструкции, такие как сложение и деление.

.Пример:
```
```
average(min(lead.values.a, lead.values.b), abs(lead.values.c))

## Variables

Движок выражений **не** позволяет определять пользовательские переменные внутри самого выражения.
Все переменные определяются системой, в которой выполняется выражение.

Доступные переменные либо документированы в пользовательском интерфейсе системы, либо на соответствующих страницах документации.

## Objects

Объекты позволяют инкапсулировать различные фрагменты информации в одну переменную, например, пользователя, роль или запись.

К примитивным объектоподобным типам данных относятся [`KV`](modules/integrator-guide/pages/expr/expr/type-reference.md#datatype-kv) и [`KVV`](modules/integrator-guide/pages/expr/expr/type-reference.md#datatype-kvv); другие объектоподобные типы данных, определяемые компонентами, можно найти [здесь](modules/integrator-guide/pages/expr/expr/type-reference.md#object-reference).

.В простейшей форме объект определяется, как показано в примере ниже:
```
```
{
  "username": "testUser",
  "email": "test@mail.tld"
}

.Если вы хотите сослаться на весь объект, следует сослаться на переменную; например:
```
```
newUser // результат: { "username": "testUser", "email": "test@mail.tld" }

.Если вы хотите сослаться на конкретные свойства объекта, следует использовать селектор; например:
```
```
newUser.username // результат: "testUser"
newUser["username"] // результат: "testUser"

!!! note
    Селектор объекта может использовать как нотацию `["<selector>"]`, так и `.<selector>`.


### Missing Properties

Обращение к отсутствующим (несуществующим) свойствам приводит к ошибке:

```
```
myKV = { "a": "value-of-a" }
myB = myKV.b // вызывает ошибку: unknown parameter myKV.b

.Используйте [тернарный оператор](https://en.wikipedia.org/wiki/%3F:) для создания простого однострочного проверочного выражения.
```
```
myB = has(myKV, "b") ? myKV.b : "b does not exist"

.Более глубокие структуры также можно проверить аналогичным образом.
```
```
deepKV = { "a": { "b": 42 } }
myB = has(deepKV, "a") && has(deepKV.a, "b") ? deepKV.a.b : "a.b does not exist"

### Missing Record Values

Значения записей можно получать так же, как и для объектов и других типов «ключ-значение».
Базовый механизм селектора для значений записей выполняет дополнительные проверки и позволяет выбирать (читать) неустановленные значения, если поле модуля существует.

```
```
hit1 = myRecord.values.existingFieldWithValueSet
hit2 = myRecord.values.existingFieldWithoutAValue

miss = myRecord.values.unknownField // вызовет ошибку: "unknown parameter myRecord.values.unknownField"

.Используйте [оператор объединения с null](https://en.wikipedia.org/wiki/Null*coalescing*operator) для создания простого однострочного проверочного выражения для неустановленных полей.
```
```
failsafe = myRecord.values.existingFieldWithoutAValue ?? 'value was not yet set'

## Arrays

Массивы позволяют инкапсулировать серию значений в одну переменную, например, список лидов или контактов, которые вы хотите создать.

[`Array`](modules/integrator-guide/pages/expr/expr/type-reference.md#datatype-array) — единственный собственный тип данных массива.
Массив может содержать любой тип данных, включая другой массив.

!!! tip
    Вложенные массивы позволяют определять многомерную матрицу.


.В простейшей форме массив определяется, как показано в примере ниже:
```
```
[{
  "username": "testUser1",
  "email": "test+1@mail.tld"
}, {
  "username": "testUser2",
  "email": "test+2@mail.tld"
}]

.Если вы хотите сослаться на весь массив, следует сослаться на переменную; например:
```
```
newUsers // результат: [{ "username": "testUser1", "email": "test+1@mail.tld" }, { "username": "testUser2", "email": "test+2@mail.tld" }]

.Если вы хотите сослаться на конкретные элементы массива, следует использовать селектор; например:
```
```
newUser[0] // результат: { "username": "testUser1", "email": "test+1@mail.tld" }
newUser[1] // результат: { "username": "testUser2", "email": "test+2@mail.tld" }

.Если вы хотите получить доступ к свойству объекта, находящегося внутри массива, следует добавить селектор объекта:
```
```
newUser[0]["email"] // результат: "test+1@mail.tld"

!!! note
    Селектор массива может использовать только нотацию `[]`.

### Order of Execution

Выражения следуют «обычному порядку» выполнения, где порядок изначально основан на **приоритете операторов**, а операторы с равным приоритетом выполняются **слева направо**.

Для примера; порядок выполнения выражения `a + b + (c + d * e)` будет следующим:

1. `d * e` (`x1`)
1. `c + x1` (`x2`)
1. `a + b` (`x3`)
1. `x3 + x2`

Порядок выполнения можно контролировать, заключая части выражения в скобки `()`.
