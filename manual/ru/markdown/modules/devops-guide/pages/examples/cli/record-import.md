# Импорт записей Low Code

!!! important
    Патч-релиз `2021.9.5` требует предоставления определений полей модуля вместе с определениями импорта записей (обратите внимание на записи полей модуля в `defs.yaml` — фрагмент ниже).
    Если определения полей не предоставлены, процесс импорта завершается ошибкой об отсутствующих полях.
    Это требование будет снято в будущем патч-релизе.


!!! caution
    Перед импортом больших наборов данных (особенно в продакшен) рекомендуется сделать резервную копию базы данных и протестировать конфигурацию локально или на staging-сервере.


.Для импорта записей Low Code вам необходимо:
1. Подготовить файлы-источники — файлы CSV или JSONL и файл(ы) определений,
1. выполнить команду.

## Файлы-источники

Подготовьте каталог, в котором будут находиться все ваши файлы-источники.

.`/import`:
```
```
/import
  /aa.csv
  /bb.csv
  /cc.csv
  /defs.yaml

Файлы `.csv` содержат записи, которые мы хотим импортировать, а `defs.yaml` содержит все определения импорта.

!!! tip
    Вы можете использовать несколько файлов определений, например, по одному на модуль.


!!! tip
    Вы можете указать определение импорта внутри ваших provision YAML-файлов.


.`defs.yaml`:
```yaml
```
namespace: my-namespace
modules:
  aa:
    fields:
      f1:
        kind: String
        label: f1
    records: <1>
      source: aa.csv <2>
      key: id <3>
      mapping: <4>
        id: / <5>
        f1: <6>
          field: f1 <7>
  bb:
    fields:
      ref_a:
        kind: Record
        label: ref_a
        options:
          module: aa
      f1:
        kind: String
        label: f1
    records:
      source: bb.csv
      key: id
      mapping:
        id: /
        ref_a:
          field: ref_a
        f1:
          field: f1
  cc:
    fields:
      ref_a:
        kind: Record
        label: ref_a
        options:
          module: aa
      ref_b:
        kind: Record
        label: ref_b
        options:
          module: bb
      f1:
        kind: String
        label: f1
    records:
      source: cc.csv
      key: id
      mapping:
        id: /
        ref_a:
          field: ref_a
        ref_b:
          field: ref_b
        f1:
          field: f1
<1> Ключ `records` содержит определения импорта записей.
<2> Ключ `source` указывает, какой файл-источник следует использовать (имя файла).
<3> Ключ `key` указывает, какая колонка должна использоваться как идентификатор записи при сопоставлении ссылок.
<4> Ключ `mapping` указывает, как колонки источника должны сопоставляться с полями модуля.
<5> Когда вы используете `/` вместо поля модуля, колонка пропускается.
<6> Ключ карты определяет колонку источника.
<7> Поле определяет поле модуля, с которым должно быть сопоставлено значение колонки.

.`aa.csv`:
```csv
```
id,f1
aa*1,aa*v_1
aa*2,aa*v_2
aa*3,aa*v_3

.`bb.csv`:
```csv
```
id,ref_a,f1
bb*1,aa*1,bb_v_1
bb*2,aa*1,bb_v_2
bb*3,aa*1,bb_v_3
bb*4,aa*2,bb_v_4
bb*5,aa*2,bb_v_5
bb*6,aa*3,bb_v_6
bb*7,aa*3,bb_v_7

!!! note
    Обратите внимание, как колонка `ref_a` в файле `bb.csv` ссылается на колонку `id` в файле `aa.csv`.


.`cc.csv`:
```csv
```
id,ref*a,ref*b,f1
cc*1,aa*1,bb*1,cc*v_1
cc*2,aa*1,bb*1,cc*v_2
cc*3,aa*3,bb*1,cc*v_3
cc*4,aa*3,bb*1,cc*v_4
cc*5,aa*3,bb*6,cc*v_5
cc*6,aa*3,bb*7,cc*v_6

## Запуск импорта

Используйте [команду CLI import](modules/devops-guide/pages/examples/cli/references/cli-reference.md#import) для импорта ваших записей.

Аргументом команды CLI должен быть путь к файлам-источникам; в нашем случае выше это `/import`.

.Пример выполнения команды CLI для нашего случая:
```bash
```
lowcode-server import --merge-left-existing /import

## Обновление записей

!!! note
    Если вы хотите обновить записи с помощью команды CLI import, вы должны использовать ID записи, который LowCoooode присвоил оригиналу.
    Процесс идентификации может измениться в будущих версиях.
