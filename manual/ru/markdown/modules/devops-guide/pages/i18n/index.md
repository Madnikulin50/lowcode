# Интернационализация

LowCoooode позволяет полностью перевести большинство аспектов системы.
От [ui-translations,пользовательского интерфейса](#ui-translations,пользовательского интерфейса) до пользовательских [resource-translations,конфигураций Low Code](#resource-translations,конфигураций Low Code), таких как модули и их поля.

Переводы пользовательского интерфейса предоставляются через статические файлы `.yaml`, которые включены в docker-образ `lowcode-server`.

Если вы хотите загрузить дополнительные или изменённые переводы, вам необходимо выполнить некоторые настройки на стороне сервера.

## Настройка системы

Выполнение следующих шагов позволит вашему инстансу LowCoooode обслуживать изменённые переводы.

!!! caution
    LowCoooode игнорирует переводы для языков, которые не определены в файле `.env`.
    См. <<languages-manage,управление языками>> для подробностей.


### Подготовка структуры файлов

Создайте новый каталог на сервере, где работает LowCoooode.

.Предположим, что структура файлов выглядит так:
```
```
📁 my-lowcode
  📄 docker-compose.yaml
  📄 .env
  📁 my-locale <1>
    📁 src <2>
<1> Мы используем каталог `my-locale` для хранения наших пользовательских переводов и соответствующих метаданных.
<2> Каталог `src` содержит файлы переводов и соответствующие файлы конфигурации.

### Конфигурации системы

Во-первых, определите том в вашем файле `docker-compose.yaml`.
Пример, следующий приведённой выше файловой системе, выглядит так:

```yaml
```
version: '3.5'

services:

  server:
    image: lowcode/lowcode:${PAGE-VERSION}.x
    restart: always
    env_file: [ .env ]
    depends_on: [ db ]
    volumes: ["./my-locale:/my-locale"] <1>

<1> Здесь вы монтируете том.

Во-вторых, вам нужно указать LowCoooode, где находятся переводы.
Это делается с помощью переменной `.env` `LOCALE_PATH`.
Пример, следующий приведённой выше конфигурации, выглядит так:

```env
```

LOCALE_PATH=../my-locale/src <1>

<1> Здесь вы определяете путь.
Если вы хотите определить несколько путей, используйте двоеточие (`:`) в качестве разделителя.
Например, `LOCALE_PATH="../my-locale-en/src:../my-locale-de/src"`.
При использовании нескольких путей определения переопределяются в том же порядке, в котором они определены.

### Применение изменений

После того как вся конфигурация установлена, вам необходимо перезагрузить конфигурации.

.Выполните:
```bash
```
docker-compose up -d

```bash
```
!!! important
    Если вы обновляете файлы переводов после запуска сервера LowCoooode, вы должны перезапустить его.
    
    .Выполните:
    docker-compose restart
    ----

## Управление доступными языками

Языки, которые вы хотите поддерживать на вашем инстансе LowCoooode, **должны** быть определены переменной `.env` `LOCALE_LANGUAGES`.

Языковой тег должен соответствовать стандарту [BCP-47](https://en.wikipedia.org/wiki/IETF*language*tag).
Обширный список языков доступен [здесь](https://www.techonthenet.com/js/language_tags.php).

Языки можно определять с помощью простого языкового тега, например `en` и `sl`.
Если вам нужно быть более точным, вы можете использовать суффикс региона, например `en-US` и `en-UK`.
LowCoooode пытается определить язык из заголовков запроса и обслуживать соответствующий перевод.

Если вы хотите определить несколько языков, их нужно разделять запятыми (`,`).

.Пример конфигурации, использующей английский, немецкий и итальянский языки:
```
```
LOCALE_LANGUAGES="en,de,it"

Чтобы включить переводы для пользовательского контента Low Code вашего LowCoooode, вы должны установить `LOCALE*RESOURCE*TRANSLATIONS_ENABLED=true`.

## Среда разработки

LowCoooode предоставляет некоторые полезные утилиты для отладки и общих переводов, которые можно включить с помощью следующих переменных `.env`.

[cols="2s,5a"]
|===
| Переменная | Описание

| [#env-locale*log]#[env-locale*log,`LOCALE*LOG`](#env-locale*log,`LOCALE_LOG`)#
| Переменная `LOCALE_LOG` заставляет сервер LowCoooode выводить журнал того, что происходит в системе.
Это может помочь вам отладить проблемы.

| [#env-locale*development*mode]#[env-locale*development*mode,`LOCALE*DEVELOPMENT*MODE`](#env-locale*development*mode,`LOCALE*DEVELOPMENT*MODE`)#
| Переменная `LOCALE*DEVELOPMENT*MODE` упрощает изменения переводов, так как файлы переводов загружаются для каждого запроса вместо загрузки при запуске.

|===

## Устранение неполадок

### Языки не загружаются как ожидалось?

Когда языки не загружаются как ожидалось, включите ведение журнала и перезапустите сервер.
Первые несколько строк журнала должны описывать, что происходит и какие языки загружены.
