# Обновление до 2020.3

## После обновления

### Скрипты Corredor

LowCoooode 2020.3 вводит новый способ хранения, обработки и выполнения скриптов автоматизации.
Код, конфигурация и триггеры больше не хранятся в базе данных LowCoooode, а определяются как файлы JavaScript в файловой системе и напрямую обрабатываются сервером LowCoooode Corredor.

Все предустановленные скрипты для CRM и ServiceCloud уже перенесены и готовы к использованию.

!!! important
    Любые пользовательские скрипты автоматизации необходимо переносить вручную.


Доступны 2 команды `script-migrator`: одна для системы, другая для сервиса Low Code:

[source,subs="attributes"]
{CLI*CMD*PREFIX} system script-migrator --dst <base-location>
{CLI*CMD*PREFIX} compose script-migrator --dst <base-location>

Эти две команды создают простую структуру в каталоге `<base-location>/<service>/custom`
(`system/custom/` и `compose/custom/`), содержащую скрипты обоих сервисов.

!!! caution
    Инструмент script-migrator напрямую экспортирует исходный код скриптов и триггеры без выполнения каких-либо проверок или тестов.
    Обязательно протестируйте каждый скрипт и триггер после миграции.


Укажите для инструмента script-migrator (base-location) каталог `usr/server` Corredor'а.
Это создаст файлы исходного кода скриптов (javascript) непосредственно в рекомендуемом месте.

Имена файлов скриптов создаются из имён скриптов (с добавлением ID скрипта в случае дубликатов).
Мигратор пропускает все удалённые скрипты, удалённые триггеры, скрипты с именем «test» или без кода.

!!! note
    Если это возможно, там, где упоминается модуль (в скриптах Compose), используется хендл модуля.
