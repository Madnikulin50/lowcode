# Обновление до 2021.3

## После обновления

### LowCoooode Workflow

LowCoooode вводит рабочие процессы как альтернативу скриптам автоматизации.
Рабочие процессы позволяют выполнять подавляющее большинство задач скриптов автоматизации, сохраняя визуальный фактор.

Настоятельно рекомендуется перенести ваши скрипты автоматизации на рабочие процессы.
Обратитесь к [руководству разработчика low-code платформы](2021.3@integrator-guide/workflows/index.md) за подробностями.

.Убедитесь, что вы выполнили частичное provision для импорта рабочих процессов и связанных разрешений:
```shell
```
docker-compose exec server lowcode-server import /lowcode/provision/300_automation

### Шаблоны

LowCoooode вводит шаблоны как стандартизированный механизм для обработки и рендеринга документов на основе универсальных шаблонов.
До версии 2021.3 шаблоны обрабатывались либо в модулях Low Code, либо как файлы `.html` и рендерились с помощью нашего пакета `lowcode-js/renderer`.
Начиная с 2021.3 вы можете определять и рендерить шаблоны напрямую с помощью ядра системы.

Настоятельно рекомендуется перенести ваши шаблоны на новый стандартизированный механизм.
Обратитесь к [руководству разработчика low-code платформы](modules/integrator-guide/pages/templates/index.md) за подробностями.

### Аутентификация

LowCoooode перерабатывает работу системы аутентификации.
Начиная с 2021.3 все эндпоинты аутентификации удалены и больше не работают.

Если вы использовали эндпоинты аутентификации для получения JWT-токена для доступа к API, вы можете использовать [JWT-команду CLI](modules/devops-guide/pages/references/cli-reference.md#auth-jwt).

Если вы использовали эндпоинты аутентификации для аутентификации пользователей на ваших собственных порталах, вам необходимо зарегистрировать клиент аутентификации на панели LowCoooode Auth и переработать логику аутентификации для использования потока OAuth 2.
