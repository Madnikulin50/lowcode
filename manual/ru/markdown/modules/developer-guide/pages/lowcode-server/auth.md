# Аутентификация и авторизация

LowCoooode реализует протокол аутентификации OAuth2.
Сервер LowCoooode может выступать как в роли OAuth2-сервера, так и в роли OAuth2-клиента, обеспечивая внутреннюю и внешнюю аутентификацию.

Обратитесь к [спецификации OAuth2](https://oauth.net/2) для полной справки по протоколу.

.Схема общего потока авторизации с LowCoooode Auth:
[plantuml,common-auth-flow,svg]
@startuml
|User|
|Client application|
|Authorization server|
if (Verify redirect URI parameter) then
    |User|
    #darkred:Failed:\nInvalid redirect URI;
    stop
endif

|Authorization server|
|User|
|Authorization server|
if (Verify credentials) then
    |User|
    #darkred:Failed:\nInvalid credentials;
    stop
endif

|Authorization server|
if (Can user authorize this client) then
    |User|
    #darkred:Failed:\nNo permissions to authorize this client;
    stop
endif

|Authorization server|
if (Is user valid) then
    |User|
    #darkred:Failed:\nInvalid user\n(eg: unverified email);
    stop
endif

|Authorization server|
if (Is client trusted) then
    |User|
endif

|Authorization server|
|Client application|
->exchange code for token;
|Authorization server|
|Client application|
#green:Store tokens;
stop;
@enduml

## Зачем переработка OAuth2?

- OAuth2 — это проверенный и широко принятый стандарт аутентификации.
- LowCoooode становится более открытым и его проще интегрировать с различными приложениями.
- Он хорошо вписывается в существующую модель безопасности RBAC.
- Персонализированная страница аутентификации позволяет пользователям чувствовать себя в безопасности при вводе своих учётных данных.
- Тривиальная модификация пользовательского интерфейса аутентификации LowCoooode.

<a id="auth-server"></a>
## Сервер аутентификации LowCoooode

Позволяет пользователям предоставлять приложениям доступ к ресурсам API LowCoooode без раскрытия их фактических учётных данных.
Это происходит через безопасный обмен учётными данными, кодами, секретами и токенами в соответствии с протоколом OAuth2.

После успешной авторизации с помощью локальных учётных данных или внешнего поставщика выдаются **токен доступа** вместе с **токеном обновления**.
Это должно выполняться клиентом автоматически.

Сессия на LowCoooode Auth отличается от сессии в клиентском приложении.
Это разделение позволяет использовать сессию LowCoooode Auth при авторизации дополнительных клиентов.

!!! caution
    Поскольку сессии аутентификации разных клиентов различаются, вы должны аннулировать каждую сессию, чтобы пользователь был «полностью вышедшим из системы».


<a id="auth-scope"></a>
## Объём авторизации

Объём определяется как серия членств в ролях, которые либо **разрешены**, либо **запрещены**, либо **принудительно назначены** пользователю при использовании конкретного сервера аутентификации LowCoooode.

[cols="2s,5a"]
|===
| [#auth-scope-permitted]#[auth-scope-permitted,Разрешённые роли](#auth-scope-permitted,Разрешённые роли)#
Разрешённые роли позволяют указать, какие роли пользователю **разрешено иметь** при доступе к ресурсам API LowCoooode от конкретного клиента.

| [#auth-scope-prohibited]#[auth-scope-prohibited,Запрещённые роли](#auth-scope-prohibited,Запрещённые роли)#
Запрещённые роли позволяют указать, какие роли пользователю **запрещено иметь** при доступе к ресурсам API LowCoooode от конкретного клиента.

| [#auth-scope-forced]#[auth-scope-forced,Принудительные роли](#auth-scope-forced,Принудительные роли)#
Принудительные роли позволяют указать, какие роли пользователь **должен иметь** при доступе к ресурсам API LowCoooode от конкретного клиента.
Если у пользователя нет принудительной роли, она будет добавлена автоматически.
|===

## Функции безопасности LowCoooode Auth

Формы аутентификации и эндпоинты защищены от атак перебором и межсайтовых атак подделки запросов.
Вы также можете задать свои секреты для шифрования значений JWT, CSRF и файлов cookie.

Различные сроки истечения можно задать для временных и постоянных сессий, чтобы соответствовать политикам безопасности вашей организации.
