# Интернационализация

!!! note
    *DevNote* сделать и для веб-приложений; нужно синхронизироваться по поводу того, где находятся компоненты и тому подобное.


LowCoooode позволяет полностью перевести большинство аспектов системы.
От пользовательского интерфейса до пользовательских конфигураций Low Code, таких как модули, поля и страницы.

Бэкенд определяет собственную систему для обработки статического и настраиваемого содержимого.
Фронтенд-приложения используют [i18next](https://www.i18next.com/) и [vue-i18next](https://github.com/panter/vue-i18next).

## Обзор структуры

### `pkg/locale`

`pkg/locale` содержит основную логику загрузки, хранения и доступа к переводам.
На интерфейсы сервисов должны ссылаться сервисы компонентов для обеспечения интернационализации.

!!! important
    Ресурсы локали загружаются в память и доступны оттуда.
    Слой хранилища и файловая система задействуются только при загрузке, перезагрузке или обновлении.


Пакет загружает переводы ресурсов из хранилища, а *статические* переводы — из файловой системы (переменная `.env` `LOCALE_PATH`).

.Важные части пакета:
- `locale.Language` (структура): инкапсулирует i18n-ресурсы для данного языка; может предоставлять ссылки на родительские языки.
- `locale.Locale` (интерфейс): определяет интерфейс доступа к ресурсам локали на основе предоставленных пространства имён и ключа.
- `locale.Resource` (интерфейс): определяет интерфейс доступа к переводам ресурсов.

### `<component>/service/locale.gen.go`

Компонент может определить сгенерированный сервис (`ResourceTranslationsManagerService`), предназначенный для предоставления и обновления переводов для ресурсов компонента, которые их поддерживают.

Сервис генерируется из файлов `def/\*.yaml`.

### `<component>/types/locale.gen.go`

Компонент может определить файл `locale.gen.go`, который определяет ключи перевода ресурсов для ресурсов компонента, а также предоставляет некоторый шаблонный код для переводов ресурсов.

Сервис генерируется из файлов `def/\*.yaml`.

## Расширение

### Добавление переводов для нового ресурса

Чтобы добавить совершенно новый ресурс, определите новый файл в каталоге `/def`.

Файл должен соответствовать шаблону: `\{component\}(.\{resource\}).yaml`.
Например: `compose.module-field.yaml`.

.Шаблон содержимого
```yaml
```
locale:
  resource:
    references: [ namespace, module, ID ]

  skipSvc: true
  keys:
    - label
    - { name: descriptionView, path: meta.description.view, custom: true, customHandler: descriptionView }

!!! note
    Здесь используется новый WIP-кодогенератор v3; запустите `go run pkg/codegen-v3/*.go def`


### Добавление переводов для существующего ресурса

Чтобы добавить перевод к существующему ресурсу, откройте файл в каталоге `/def`.

Файл должен соответствовать шаблону: `\{component\}(.\{resource\}).yaml`.
Например: `compose.module-field.yaml`.

Если файл ещё не существует, создайте его.

Добавьте запись в раздел `locale.keys`

.Шаблон содержимого
```yaml
```
locale:
  resource:
    references: [ namespace, module, ID ]

  skipSvc: true
  keys:
    - label
    - { name: descriptionView, path: meta.description.view, custom: true, customHandler: descriptionView }

!!! note
    Здесь используется новый WIP-кодогенератор v3; запустите `go run pkg/codegen-v3/*.go def`


## Эндпоинты для доступа к переводам ресурсов

Если компонент определяет ресурсы, поддерживающие переводы, генерируется сервис локали.
Вам необходимо подключить REST-эндпоинты к сгенерированному сервису, чтобы предоставить функции для вывода списка и обновления этих переводов.

!!! important
    Каждый ресурс, поддерживающий переводы, должен определять свои собственные REST-эндпоинты.
    Например, и пространства имён, и модули имеют свои собственные эндпоинты.


.Чтобы подключить его к REST-эндпоинту:
1. обновите определение `<component>/rest.yaml` эндпоинтом списка/обновления переводов (см. `compose/rest.yaml`; пространство имён, модуль в качестве примера)
1. добавьте необходимые методы REST-обработчика и подключите их к сгенерированному сервису (см. `compose/rest/namespace.go`)

## Перевод ресурсов

Для обеспечения обратной совместимости перевод применяется к запрошенному ресурсу (пространству имён, модулю) сервисом компонента.

Например, сервис `compose/namespace` переведёт запрошенное пространство имён на язык, определяемый HTTP-заголовком `Accept-Language` запроса.

Обратитесь к функции `compose/service/namespace.go@Find` для примера.

Обратитесь к функции `compose/service/module.go@Find` для более сложного примера, когда ресурс расширяется.

## Обновление переводов на основе ресурса

Для обеспечения обратной совместимости, когда ресурс создаётся/обновляется, переводы ресурса **могут** также обновляться.

Например, сервис `compose/namespace` соберёт параметры `name`, `subtitle` и `description`; возьмёт HTTP-заголовок `Content-Language` запроса для обновления хранилища.

Обратитесь к функции `compose/service/namespace.go@Update` для примера.

Обратитесь к функции `compose/service/module.go@Update` для более сложного примера, когда ресурс расширяется.
