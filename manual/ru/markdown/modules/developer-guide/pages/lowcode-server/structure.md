# Структура проекта

## `/app`

Пакет `app` обрабатывает все процедуры инициализации, такие как разбор `.env`, настройка хранилища, инициализация сервисов и инициализация API.

## `/cmd`

Пакет `cmd` инициализирует команды CLI, предоставляемые `lowcode-server`

## `/provision`

Каталог `/provision` содержит все основные ресурсы, используемые при выполнении шага провижининга.
Сюда входят базовые роли, контроль доступа и встроенные расширения (CRM и управление обращениями).

!!! caution
    Это не миграция базы данных.
    Миграцией базы данных занимается пакет `store`.


## `/webapp`

Каталог `/webapp` используется для подготовки и обслуживания веб-приложений непосредственно из бинарного файла `lowcode-server`.
Это устраняет необходимость в локальной настройке веб-приложений для доступа к ним.

Обратитесь к `/webapp/README.adoc` за подробностями.

## `/auth`

Пакет `auth` обрабатывает функциональность аутентификации.
Пакет определяет сервисы, эндпоинты API и любые дополнительные «служебные пакеты», необходимые для аутентификации.

Помимо основной логики, пакет также определяет шаблоны пользовательского интерфейса аутентификации и базовые ресурсы.

## `/system`

Пакет `system` обрабатывает основную системную функциональность, такую как управление пользователями, ролями и шаблонами.
Пакет определяет сервисы, эндпоинты API и любые дополнительные «служебные пакеты», необходимые для основной системы.

## `/compose`

Пакет `compose` обрабатывает функциональность Compose, такую как управление пространствами имён, модулями и записями.
Пакет определяет сервисы, эндпоинты API и любые дополнительные «служебные пакеты», необходимые для системы Compose.

## `/automation`

Пакет `automation` обрабатывает функциональность автоматизации, такую как управление и выполнение рабочих процессов.
Пакет определяет сервисы, эндпоинты API и любые дополнительные «служебные пакеты», необходимые для системы автоматизации.

## `/federation`

Пакет `federation` обрабатывает функциональность федерации данных, настройку общих данных и синхронизацию изменений данных.
Пакет определяет сервисы, эндпоинты API и любые дополнительные «служебные пакеты», необходимые для системы федерации.

!!! note
    Пакет федерации связан с сервисом `compose` как его источником данных.


## `/docs`

Каталог `/docs` используется для хранения документации API.
Документация генерируется с помощью инструмента [openapi3-converter](https://github.com/lowcode/openapi3-converter/tree/develop).

## `/pkg`

Каталог `/pkg` содержит общие пакеты, используемые в остальной части системы.

Пакеты, находящиеся в каталоге `/pkg`, не должны определять явных зависимостей друг от друга, а также от сервисов, в которых они могут использоваться.

## `/store`

Пакет `store` определяет слой хранилища, используемый LowCoooode.
Слой хранилища — это общий интерфейс к любой из поддерживаемых баз данных, таких как PostgreSQL и MySQL.

Помимо основной логики, пакет store определяет логику, специфичную для драйверов баз данных (такую как кодирование данных и приведение типов данных), а также процедуры миграции схем, такие как `store/rdbms/rdbms*schema.go` и `store/rdbms/generic*upgrades.go` для реляционных баз данных.

## `/tests`

Каталог `/tests` содержит интеграционные тесты, сгруппированные по сервису, для которого они определены (`compose`, `system`, ...).
