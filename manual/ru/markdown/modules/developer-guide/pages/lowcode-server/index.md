# LowCoooode Server

[LowCoooode server](https://github.com/lowcode/lowcode-server) — это бэкенд экосистемы LowCoooode.
Основная логика написана на GO с использованием [go-chi](https://pkg.go.dev/github.com/go-chi/chi@v3.3.4+incompatible?utm_source=gopls) для маршрутизации.

Связь между сервером LowCoooode и веб-приложениями осуществляется через REST API и веб-сокеты.
Связь между бэкенд-сервисами (сервер LowCoooode и Corredor) осуществляется через gRPC.

Небинарные данные обрабатываются слоем хранилища и сохраняются в базе данных — в настоящее время PostgreSQL и MySQL.
В будущем мы добавим поддержку дополнительных баз данных.

Бинарные данные обрабатываются с использованием minIO и хранятся либо локально, либо в поддерживаемом облачном провайдере.

## Настройка разработки

!!! caution
    Сервер LowCoooode работает на GO 1.24.1.
    В этом руководстве предполагается, что ваша среда разработки GO уже настроена на правильную версию.


### Форк сервера LowCoooode

!!! caution
    Основные участники могут пропустить эту часть.


1. перейдите в репозиторий https://github.com/{GIT*REPO*GROUP}/{GIT*REPO*PREFIX}-server
1. нажмите кнопку btn:[Fork] в правом верхнем углу и следуйте инструкциям на экране.

### Клонирование репозитория

.С помощью CLI:
1. откройте CLI
1. перейдите в вашу рабочую папку
1. выполните команду `git clone git@github.com:$YOUR*USERNAME*HERE/lowcode-server.git`

!!! tip
    Обратитесь к https://github.com/lowcode/lowcode-server[репозиторию], если вы хотите использовать альтернативный метод.


### Настройка окружения

.Внутри вашего каталога `lowcode-server`:
1. выполните `cp .env.example .env`
1. откройте файл `.env` с помощью VIM, Nano или любого другого редактора и измените конфигурацию по своему усмотрению

### Настройка хранения данных

Если ваша работа требует постоянного хранения, убедитесь, что вы настроили поддерживаемый движок базы данных.
Базу данных можно запустить как локально, так и внутри Docker-контейнера.
Убедитесь, что вы изменили переменную `.env` `DB_DSN=`.

Если ваша работа не требует постоянного хранения (вы будете работать исключительно с тестами), вы можете пропустить этот шаг, и тестовый фреймворк будет использовать встроенный SQLite-сервер.
Убедитесь, что вы удалили переменную `.env` `DB_DSN=`.

### Настройка SMTP

Для локальной разработки вы можете использовать MailHog для логирования писем, отправляемых с сервера.
Выполните команду `make mailhog.up`, чтобы запустить MailHog.
В качестве альтернативы вы можете использовать реального SMTP-провайдера, такого как Gmail или MailGun.
Убедитесь, что вы изменили переменные `.env` `SMTP_*=`.

Вы можете пропустить эту часть, если ваш рабочий процесс не требует писем.
Убедитесь, что вы удалили переменные `.env` `SMTP_*=`.

### Обслуживание веб-приложений

Сервер LowCoooode позволяет обслуживать все веб-приложения LowCoooode для случаев, когда вам нужно быстро проверить что-то на пользовательском интерфейсе.
Обратитесь к файлу `lowcode-server/webapp/README.adoc` за подробностями о том, как это настроить.

!!! caution
    Убедитесь, что вы правильно задали переменную `.env` `HTTP_ADDR`, чтобы она соответствовала вашему локальному окружению, например `HTTP_ADDR=localhost:80`.
    Значение по умолчанию `HTTP_ADDR` — `HTTP_ADDR=localhost:80`.
    
    Порт 80 недоступен в Windows.


!!! caution
    Сервер аутентификации использует переменные `HTTP_ADDR` и `DOMAIN` при генерации файлов cookie.
    Поток аутентификации зависнет, если они не определены.
    
    Если экран входа _ничего не делает_, когда вы пытаетесь войти, проверьте, установлен ли для cookie правильный домен.


### Запуск сервера

Выполните команду `make watch`, чтобы запустить сервер.
Сервер автоматически перезапускается при обнаружении изменений в коде.

!!! caution
    Наблюдатель иногда может работать со сбоями.
    Перезапустите сервер вручную, если изменения не подхватываются.


### Запуск тестов

.Есть несколько команд для запуска ваших тестов:
- `test.integration` для запуска интеграционных тестов (тестовые файлы в `/tests`)
- `test.store` для запуска тестов хранилища (тестовые файлы в `/store/tests`)
- `test.all` для запуска всех тестов
- `test.unit` для запуска модульных тестов
- `test.pkg` для запуска тестовых файлов для каталога `/pkg`

!!! tip
    Все команды, кроме `test.all`, принимают дополнительный аргумент `.$WHAT_TO_TEST`.
    Например, чтобы запустить только интеграционные тесты Compose, вы выполните команду `make test.integration.compose`


!!! caution
    *Подвох интеграционного тестирования:*
    
    Чтобы предотвратить взаимодействие ваших тестов с вашей рабочей базой данных, вы можете определить файл `.env`, специфичный для интеграционного тестирования, внутри каталога `/tests`.
    Там вы можете настроить другую базу данных или удалить её, чтобы использовать встроенную SQLite-базу данных.
    
    *Подвох тестирования хранилища:*
    
    Один и тот же тестовый набор запускается во всех поддерживаемых базах данных.
    Если вы хотите протестировать конкретную базу данных, вы должны определить соответствующий `DSN` в корневом файле `.env`.
    Обратитесь к `/store/tests/main_test.go` за подробностями.
    
    См. раздел <<container-db,настройка контейнерной базы данных>>, если вы хотите запускать свои тестовые базы данных в контейнере.

# Настройка контейнеризованной базы данных

## MySQL

Обычно мы используем форк [Percona](https://hub.docker.com/_/percona) базы данных MySQL.

.Используйте следующие команды для настройки переменных окружения; при необходимости замените значения:
```bash
```
export DOCKER_NAME=percona;
export ROOT_PWD=root;
export MYSQL_PORT=3306;

.Для настройки базы данных выполните следующие шаги:
1. `docker run --name $DOCKER*NAME -e MYSQL*ROOT*PASSWORD=$ROOT*PWD -d -p $MYSQL_PORT:3306 percona:8.0;`
1. `docker exec -it $DOCKER*NAME mysql -uroot -p$ROOT*PWD;`
1. `CREATE DATABASE lowcode;`
1. `CREATE USER 'lowcode'@'172.17.0.1' IDENTIFIED BY 'lowcode';`
1. `GRANT ALL PRIVILEGES ON lowcode.* TO 'lowcode'@'172.17.0.1';`
1. `FLUSH PRIVILEGES;`

.Используйте следующий шаблон для создания переменной [`DB*DSN`](modules/devops-guide/pages/references/configuration/server.md#*db_dsn) `.env`:
[source,.env]
DB*DSN="lowcode:lowcode@tcp(localhost:$MYSQL*PORT)/lowcode?collation=utf8mb4*general*ci"

## PostgreSQL

Обычно мы используем официальный образ [PostgreSQL](https://hub.docker.com/_/postgres).

.Используйте следующие команды для настройки переменных окружения; при необходимости замените значения:
```bash
```
export DOCKER_NAME=pgsql2;
export ROOT_PWD=root;
export PGSQL_PORT=5432;

.Для настройки базы данных выполните следующие шаги:
1. `docker run --name $DOCKER*NAME -e POSTGRES*PASSWORD=$ROOT*PWD -d -p $PGSQL*PORT:5432 postgres:13;`
1. `docker exec -it $DOCKER_NAME psql -U postgres;`
1. `CREATE DATABASE lowcode;`
1. `CREATE USER lowcode WITH PASSWORD 'lowcode';`
1. `GRANT ALL PRIVILEGES ON DATABASE lowcode TO lowcode;`

.Используйте следующий шаблон для создания переменной [`DB*DSN`](modules/devops-guide/pages/references/configuration/server.md#*db_dsn) `.env`:
[source,.env]
DB*DSN="postgres://lowcode:lowcode@localhost:$PGSQL*PORT/lowcode?sslmode=disable"

## SQLServer

!!! note
    Это черновик, чтобы эти инструкции не потерялись; будет доработано позже.


Используйте один из следующих образов:

- `SQLServer 2022`: mcr.microsoft.com/mssql/server:2022-latest
- `SQLServer 2017`: mcr.microsoft.com/mssql/server:2017-latest
- `SQLServer 2019`: mcr.microsoft.com/mssql/server:2019-CU10-ubuntu-20.04


.Пример docker-compose для всех трёх образов:
```yaml
```
  mssql_2022:
    image: mcr.microsoft.com/mssql/server:2022-latest
    restart: on-failure
    ports: [ "127.0.0.1:1433:1433" ]
    volumes:
      - "dbdata*mssql*2022:/var/opt/mssql"
    environment:
        - ACCEPT_EULA=Y
        - SA_PASSWORD=SUPERSECRET123

  mssql_2017:
    image: mcr.microsoft.com/mssql/server:2017-latest
    restart: on-failure
    ports: [ "127.0.0.1:1433:1433" ]
    volumes:
      - "dbdata*mssql*2017:/var/opt/mssql"
    environment:
        - ACCEPT_EULA=Y
        - SA_PASSWORD=SUPERSECRET123

  mssql_2019:
    image: mcr.microsoft.com/mssql/server:2019-CU10-ubuntu-20.04
    restart: on-failure
    ports: [ "127.0.0.1:1433:1433" ]
    volumes:
      - "dbdata*mssql*2019:/var/opt/mssql"
    environment:
        - ACCEPT_EULA=Y
        - SA_PASSWORD=SUPERSECRET123

.Для настройки базы данных выполните следующие шаги:
1. `docker compose exec -it mssql_2022 sh`
1. /opt/mssql-tools/bin/sqlcmd -S localhost -U sa -P "SUPERSECRET123"
1. `CREATE DATABASE lowcode;`
1. `GO`

Пример DSN базы данных: `sqlserver://sa:SUPERSECRET123@localhost:1433?database=lowcode`

## Процедура установки

Изначальная процедура находится в корневом пакете `app`, который определяет оркестрационные структуры для настройки, инициализации и запуска различных частей системы.

!!! note
    Команды CLI запускают процедуры загрузки от первого (установка) до уровня, требуемого командой.


### Уровни процедуры установки

[cols="1s,5a"]
|===
| [#setup-level-setup]#[setup-level-setup,Установка](#setup-level-setup,Установка)#
|
Настраивает и инициализирует низкоуровневые компоненты, структуры, требуемые на протяжении всего жизненного цикла.

.Более заметные компоненты:
- **Логирование**: корневое средство логирования, поддерживающее понятные человеку (форматирование, цвета) или машиночитаемые (JSON) форматы,
- **Проверка работоспособности**: планировщик, электронная почта и проверки Corredor,
- **Sentry**: sentry можно использовать как сервис отчётности об ошибках (критически важные процедуры могут использовать свои собственные функции отчётности об ошибках/панике),
- **Электронная почта**: SMTP-сервис для пересылки отправленных электронных писем,
- **Мониторинг**: примитивное логирование использования ресурсов,
- **Планировщик**: средство, управляющее интервальным выполнением автоматизаций,
- **Corredor**: клиент сервера для сервера Corredor.

!!! note
    .Когда SMTP отключён (не настроен SMTP-хост):
    * Регистрация пользователя больше не требует подтверждения по электронной почте,
    * сброс пароля отключён,
    * отправка писем через автоматизацию отключена.


| [#setup-level-db]#[setup-level-db,Инициализация хранилища](#setup-level-db,Инициализация хранилища)#
|
Устанавливает соединение с настроенной базой данных.
Процедуры после установления соединения выполняют миграции базы данных для приведения схемы к текущей версии.

| [#setup-level-services]#[setup-level-services,Инициализация сервисов](#setup-level-services,Инициализация сервисов)#
|
Инициализирует все сервисы, а также RBAC, переводы ресурсов и (если включено) федерацию.

| [#setup-level-provision]#[setup-level-provision,Провижининг](#setup-level-provision,Провижининг)#
|
Шаг провижининга гарантирует, что исходные ресурсы (пользователи, роли, пространства имён, ...) импортированы из файлов провижининга.

| [#setup-level-activate]#[setup-level-activate,Активация](#setup-level-activate,Активация)#
|
Все ранее инициализированные и настроенные сервисы запускаются/активируются, включая их наблюдатели.
