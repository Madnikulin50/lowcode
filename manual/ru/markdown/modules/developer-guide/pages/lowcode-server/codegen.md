# Генерация кода

Так как GO «немного жёсткий» в отношении обобщённых вещей, мы используем генерацию кода, когда это возможно.
Основная логика генерации кода находится в пакете `pkg/codegen`.

Определения предоставляются в виде YAML-файлов по всему исходному коду; шаблоны определены в папке `pkg/codegen/assets`.

## Запуск кодогенератора

!!! caution
    Вам необходимо <<codegen-bin-remove,удалить старый бинарный файл кодогенератора>> всякий раз, когда изменяется исходный код.
    Команды кодогенератора скомпилируют бинарный файл, если его нет.


.Запустите кодогенератор, выполнив:
```bash
```
make codegen

.Запустите кодогенератор при изменениях, выполнив:
```bash
```
make watch.codegen

<a id="codegen-bin-remove"></a>
.Удалите старый бинарный файл кодогенератора, выполнив:
```bash
```
make clean.codegen

## Расширение существующего кодогенератора

### REST API

Кодогенератор генерирует обработчики запросов REST API и разбор запросов.

!!! caution
    Документация генерируется с помощью инструмента https://github.com/lowcode/openapi3-converter/tree/develop[openapi3-converter], а не кодогенератора.


.YAML-определения:
- `*/rest.yaml`

.Файлы шаблонов:
- `rest_handler.go.tpl`
- `rest_request.go.tpl`

### Типы

Кодогенератор генерирует общие получатели наборов типов и шаблонную логику для таких функций, как метки ресурсов.

.YAML-определения:
- `\*/*/types.yaml`

.Файлы шаблонов:
- `type_labels.gen.go.tpl`
- `type_set.gen.go.tpl`
- `type*set.gen*test.go.tpl`

### Действия

Кодогенератор генерирует доступные действия сервисов вместе со свойствами и ошибками.
Эти действия в основном используются для журнала действий.

.YAML-определения:
- `**/services/**_actions.yaml`

.Файлы шаблонов:
- `actions.gen.go.tpl`

### События

Кодогенератор генерирует доступные события, которые система может испускать из различных сервисов.
Эти события в основном используются шиной событий для автоматизации.

.YAML-определения:
- `*/service/event/events.yaml`

.Файлы шаблонов:
- `events.gen.adoc.tpl`
- `events.gen.go.tpl`
- `events.go.tpl`

### Интерфейс хранилища и его реализации

Кодогенератор генерирует весь интерфейс хранилища.
В случае РСУБД также генерируется реализация.

.YAML-определения:
- `store/*.yaml`

.Файлы шаблонов:
- `store_base.gen.go.tpl`
- `store*interfaces*joined.gen.go.tpl`
- `store_partials.go.tpl`
- `store_rdbms.gen.go.tpl`
- `store*test*all.gen.go.tpl`

### Параметры

Кодогенератор генерирует все определённые параметры, доступные из переменных файла `.env`.
Параметры могут определять значения по умолчанию, а также любую предварительную обработку.

.YAML-определения:
- `pkg/options/*.yaml`

.Файлы шаблонов:
- `options.gen.adoc.tpl`
- `options.gen.go.tpl`

### Обработчики функций автоматизации

Кодогенератор генерирует определения и обёртки для обработчиков функций.
Вы по-прежнему должны вручную определять основную логику обработчика.

.YAML-определения:
- `**/automation/**_handler.yaml`

.Файлы шаблонов:
- `afunc.gen.go.tpl`

### Типы выражений

Кодогенератор генерирует типы выражений и правила приведения.
Для более сложных типов (таких как `ComposeRecord`) пользовательское приведение и операции могут быть определены вручную.

.YAML-определения:
- `\*/*/expr_types.yaml`

.Файлы шаблонов:
- `expr_types.gen.go.tpl`

## Определение нового кодогенератора

Используйте одну из существующих реализаций как основу и адаптируйте её под свои нужды.
Общая схема такова: вы **определяете шаблон**, **yaml-файлы** и **код, объединяющий оба**.

## Планы на будущее

Определите файлы `*/type.yaml`, описывающие структуру каждого известного типа.
Одно и то же определение типа должно использоваться для извлечения типов выражений и других частей, таких как события.
